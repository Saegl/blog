This page builds the Knuth–Morris–Pratt algorithm (KMP) from the ground up. We start with the search everyone writes first, watch closely where it wastes work, and repair it one observation at a time. Four ideas you said were shaky are built on the way, each at the moment it is needed and each marked as a detour: borders of a string, loop invariants, amortized analysis, and (in the extensions) finite automata.

Three objects appear on every screen, and each keeps one colour throughout: the text we search in, the pattern we search for, and borders, the piece of knowledge KMP reuses. Green marks characters that matched and coral marks a mismatch.

01A search that cannot go back

You are watching a server log as it is written:

tail -f app.log | grep "connection reset"

The log is a stream. Bytes arrive, the matcher looks at them, and they are gone. Now suppose the matcher has just read connection res and the next byte is not e. The search you would write on a whiteboard says: go back to the character after the c where this attempt started and try again from there. But those characters have already flowed past. To go back you would have to keep a buffer as long as the pattern and re-read it, again and again.

The question this page answers is whether going back is ever necessary. It is not. There is a way to search that reads each character of the text exactly once, in order, never revisits one, and in total does at most twice as many character comparisons as the text has characters, no matter how nasty the input. Morris hit exactly this problem while writing a text editor in 1970, and the algorithm he and Pratt wrote down, later published together with Knuth, is the subject here.

The same guarantee matters wherever the input is adversarial or huge: a DNA read searched in a genome, a signature scanned for in network traffic, a judge on LeetCode feeding you "aaaa…ab".

02The problem

We are given two strings. The text is the long one, with \(n\) characters; in code \(n\) is len(text). The pattern is the short one, with \(m\) characters; in code \(m\) is len(pattern). We want every index of the text at which a copy of the pattern starts.

Occurrences are allowed to overlap. In the text "aaaaaa" the pattern "aaa" starts at 0, 1, 2 and 3, and all four count.

03The obvious solution

Try every starting position. At each one, compare the pattern with the text character by character, and stop at the first difference.

def naive_search(text: str, pattern: str) -> tuple[list[int], int]:
    """Return (start index of every occurrence, number of character comparisons)."""
    match_starts: list[int] = []
    comparison_count = 0
    last_start = len(text) - len(pattern)
    for start in range(last_start + 1):
        matched_count = 0
        while matched_count < len(pattern):
            comparison_count += 1
            if text[start + matched_count] != pattern[matched_count]:
                break
            matched_count += 1
        if matched_count == len(pattern):
            match_starts.append(start)
    return match_starts, comparison_count

Problem 3.1 easy

Without running anything: how many comparisons does naive_search make for the text "aaaaaaaaaaab" (eleven as and a b) and the pattern "aaab"?

Solution

The text has 12 characters and the pattern 4, so the starts are 0 through 8: nine of them.

At starts 0 through 7 the window is "aaaa". The first three comparisons succeed and the fourth (a against b) fails: 4 comparisons each. At start 8 the window is "aaab" and all 4 comparisons succeed.

Total: \(9 \times 4 = 36\), which is what the program printed. A common slip is to count 12 starts instead of 9; the pattern has to fit, so the last start is \(n - m\).

Problem 3.2 medium

Generalise: the text is \(n-1\) copies of a followed by b, and the pattern is \(m-1\) copies of a followed by b. Give the exact comparison count as a formula, and check it against the 4,750,500 above.

Solution

There are \(n - m + 1\) starts. At every start the first \(m-1\) comparisons succeed (a against a) and then the \(m\)-th is made: it fails everywhere except at the last start. Either way, each start costs exactly \(m\) comparisons.

\[ \text{comparisons} = (n - m + 1)\cdot m \]

With \(n = 10000\) and \(m = 500\): \(9501 \times 500 = 4{,}750{,}500\). When \(m\) is about \(n/2\) this is about \(n^2/4\): quadratic.

04What the obvious solution forgets

Freeze the naive search at its first mismatch on the running example.

The naive search now moves to start 1 and asks: is text[1] equal to pattern[0]? It looks at the text to find out. But it does not need to look. Four comparisons just succeeded, and a successful comparison is a fact about the text:

The observation everything rests on

If the first \(k\) characters of the pattern have just matched at some start, then those \(k\) characters of the text are pattern[:k]. We know them without looking. Any question about that stretch of text is really a question about the pattern alone.

Here \(k = 4\), so text[0:4] is "coco", because pattern[:4] is "coco". So:

  • Start 1 would compare text[1] with pattern[0]. We know text[1] is pattern[1] = "o", and pattern[0] = "c". Start 1 is dead, and we know that from the pattern alone.
  • Start 2 would compare text[2], text[3] with pattern[0], pattern[1]. We know text[2:4] is pattern[2:4] = "co", and pattern[:2] = "co". Those two comparisons are guaranteed to succeed. Start 2 is alive, and its first two comparisons are already done.

The naive search wastes work in two distinct ways, and both come from forgetting what it just learned:

  1. It tries starts that are provably dead (start 1, start 3).
  2. At starts that are alive, it re-compares characters whose outcome is already known (the "co" at start 2).

Both wastes are decided by the pattern. And the pattern is available before the text is, so we can work all of this out once, in advance, for every possible \(k\). That advance work is the whole of KMP. To do it we need one piece of vocabulary.

Problem 4.1 easy

The pattern is "abcabd". At some start the first five characters matched and the sixth did not. Without knowing anything else about the text, which of the next four starts (one, two, three and four steps to the right) are certainly dead?

Solution

The five known text characters are pattern[:5] = "abcab". Slide the pattern under them:

  • One step right: the pattern's a sits under the known b. Dead.
  • Two steps: a under c. Dead.
  • Three steps: ab under ab. Alive, with two characters already matched.
  • Four steps: a under b. Dead.

So shifts 1, 2 and 4 are dead and only shift 3 survives among these. (Shift 5 moves past everything known, so it cannot be ruled out either. We will come back to why shift 3 is the one to take.)

05Detour: prefixes, suffixes, borders

Detour

You marked this as shaky, so it is built from nothing here. It is worth the stop: the single word border turns the vague "the pattern overlaps with itself" into something we can compute.

Take the word "alfalfa".

A prefix is what you get by keeping some characters from the start: "", "a", "al", "alf", …, "alfalfa". In Python the prefix of length length is word[:length].

A suffix is what you get by keeping some characters from the end: "", "a", "fa", "lfa", …, "alfalfa". In Python the suffix of length length is word[len(word) - length:].

A prefix or suffix is proper if it is not the whole word. The empty string counts as a proper prefix and as a proper suffix of any non-empty word.

Definition

A border of a word is a string that is both a proper prefix and a proper suffix of it. Equivalently: a length \(L\) with \(0 \le L < \text{len(word)}\) such that the first \(L\) characters equal the last \(L\) characters.

For "alfalfa": the first 4 characters are "alfa" and the last 4 are "alfa", so "alfa" is a border. So is "a". So is the empty string, always. Nothing else is: the first 2 are "al" but the last 2 are "fa".

Two things about borders surprise people. First, the two copies may overlap: in "alfalfa" the prefix "alfa" occupies indexes 0–3 and the suffix "alfa" occupies 3–6, sharing the middle a. Second, "proper" matters: without it every word would be its own border and the concept would be useless.

A direct translation of the definition into code:

def border_lengths_brute_force(word: str) -> list[int]:
    """Every length L (0 < L < len(word)) such that the first L characters equal the last L."""
    return [
        length
        for length in range(1, len(word))
        if word[:length] == word[len(word) - length:]
    ]


def border_table_brute_force(pattern: str) -> list[int]:
    """border_length[end_index] = length of the longest border of pattern[: end_index + 1]."""
    border_length: list[int] = []
    for end_index in range(len(pattern)):
        prefix = pattern[: end_index + 1]
        border_length.append(max(border_lengths_brute_force(prefix), default=0))
    return border_length

Problem 5.1 easy

List every non-empty border of "tartar", "onion", "ababa" and "level".

Solution
  • "tartar": first 3 = "tar" = last 3. Lengths 1, 2, 4, 5 fail (for example first 1 is "t", last 1 is "r"). Borders: "tar".
  • "onion": first 2 = "on" = last 2. Borders: "on".
  • "ababa": "a" (length 1) and "aba" (length 3, overlapping in the middle). Length 2 fails: "ab" against "ba".

Problem 5.2 medium

A word has length 10 and a border of length 7. Show that its characters at indexes 0, 3, 6 and 9 are all equal.

Hint

Write out what "the first 7 characters equal the last 7 characters" says position by position. The last 7 start at index 3.

Solution

The prefix of length 7 is word[0:7] and the suffix of length 7 is word[3:10]. They are equal, so position by position word[i] == word[i + 3] for every i from 0 to 6.

Apply that with i = 0, then i = 3, then i = 6: word[0] == word[3] == word[6] == word[9].

This is a first glimpse of a fact section 13 leans on: a border of length \(L\) in a word of length \(n\) is the same thing as the word repeating itself every \(n - L\) characters.

06Which shifts can survive?

Back to the search. We matched the first \(k\) characters of the pattern and then hit a mismatch. We know the last \(k\) characters of the text: they are pattern[:k]. We want to move the pattern to the right. How far?

Moving it right by a shift \(s\) puts the start of the pattern under the known characters, with \(k - s\) columns of overlap. That shift can only lead to an occurrence if every overlapping column agrees. Try it by hand on a case with a long matched part:

Now read off, in symbols, what "every overlapping column agrees" says. On top, the overlap is the last \(k - s\) known characters: the suffix of pattern[:k] of length \(k-s\). Below, it is the first \(k - s\) characters of the pattern: the prefix of pattern[:k] of length \(k-s\). They must be equal. A prefix that equals a suffix: that is a border.

Shifts are borders

After matching \(k\) characters, moving the pattern right by \(s\) (with \(1 \le s \le k\)) can lead to an occurrence only if pattern[:k] has a border of length \(k - s\). A long border means a short shift, and the other way round.

Which surviving shift should we take? The smallest one. Every smaller shift is provably dead, so skipping those loses nothing. But a surviving shift might be a real occurrence, so we must not jump over it. The smallest shift corresponds to the longest border.

And here is the part that removes the second waste. Say the longest border of pattern[:k] has length \(b\). After shifting by \(k - b\), the first \(b\) characters of the pattern sit under text characters that are already known to equal them. So we do not re-compare. We simply say: \(b\) characters are matched now, and we carry on comparing pattern[b] with the very text character that caused the mismatch.

The KMP rule

On a mismatch after \(k \ge 1\) matched characters: set the number of matched characters to \(b\), the length of the longest border of pattern[:k]. Do not move in the text. Compare again.

On a mismatch with \(k = 0\): nothing is known, so move to the next text character.

The text position never decreases. The backward walk of the naive search is gone.

Problem 6.1 easy

For each matched part, give the new number of matched characters and the distance the pattern slides: (a) "abcab", (b) "aaaa", (c) "abcd", (d) "abracadabra".

Solution

New matched count = length of the longest border; slide = \(k\) minus that.

  • (a) "abcab", \(k=5\): longest border "ab". Matched count 2, slide 3.
  • (b) "aaaa", \(k=4\): longest border "aaa". Matched count 3, slide 1. A word made of one letter is the worst case for sliding: you only ever move one step. But you still do not re-compare the three as.
  • (c) "abcd", \(k=4\): no non-empty border. Matched count 0, slide 4: the pattern jumps past everything.
  • (d) "abracadabra", \(k=11\): longest border "abra". Matched count 4, slide 7.
Problem 6.2 medium

A friend proposes to always fall back to the shortest non-empty border, "because that shifts further and is faster". Find a text and a pattern where this misses an occurrence.

Hint

You need a matched part with at least two non-empty borders. Words made of one letter have plenty.

Solution

Text "aaaab", pattern "aaab". At start 0 the first three characters match (\(k = 3\)), then text[3] = "a" meets pattern[3] = "b".

The matched part "aaa" has borders "aa" and "a". The longest, "aa", slides the pattern by 1, to start 1, where the occurrence text[1:5] = "aaab" really is.

The friend's rule takes "a" and slides by 2, to start 2. From there text[2:] is "aab", too short to hold the pattern. The occurrence at start 1 was jumped over.

Larger shifts are only safe when every smaller one is dead, and a longer border is exactly a smaller shift that is not dead.

07The border table

The rule needs one number for every possible \(k\): the length of the longest border of pattern[:k]. There are only \(m\) possible values of \(k\), so we compute them all before the search starts and store them in a list.

Definition

border_length[end_index] is the length of the longest border of the prefix that ends at end_index, that is, of pattern[: end_index + 1].

That is the list [0, 0, 1, 2, 0] printed by border_table_brute_force in the code of section 5. The same table goes by several other names: the prefix function (written \(\pi\)), the failure function, and on LeetCode usually lps, for "longest proper prefix which is also a suffix".

The off-by-one to get right once

The table is indexed by the last index of a prefix, while the search thinks in terms of how many characters matched. The prefix of length \(k\) ends at index \(k - 1\). So the fallback is matched_count = border_length[matched_count - 1]. Almost every broken KMP has this line wrong.

It helps to draw the table as a picture. Make one node for every possible value of matched_count, from 0 to \(m\). A yellow arrow leads one node forward and is labelled with the pattern character that has to match. A lavender arc leads from a node back to where a mismatch sends you. To keep the picture readable, arcs to node 0 are left out: a node with no arc falls back to 0.

Problem 7.1 easy

Write the border table for "onion", "aaaa" and "abcabcd".

Solution
  • "onion": prefixes o, on, oni have no border; onio has o; onion has on. Table [0, 0, 0, 1, 2].
  • "aaaa": a → 0, aa → 1, aaa → 2, aaaa → 3. Table [0, 1, 2, 3]. The first entry is 0, not 1: the border must be proper.
  • "abcabcd": [0, 0, 0, 1, 2, 3, 0]. The run 1, 2, 3 grows while the second abc copies the first, and the final d destroys every border at once.
Problem 7.2 medium

In all three tables above, each entry is at most one more than the entry before it. Is that always true? Explain why, or give a counterexample.

Solution

It is always true: border_length[i + 1] <= border_length[i] + 1.

Suppose the prefix ending at index \(i+1\) has a border of length \(L \ge 1\). Its first \(L\) characters equal its last \(L\) characters. Delete the last character from both copies. What is left of the first copy is pattern[:L-1]; what is left of the second copy is the last \(L-1\) characters of the prefix ending at index \(i\). They are still equal, so the prefix ending at \(i\) has a border of length \(L - 1\). Hence \(L - 1 \le\) border_length[i].

Entries can rise by at most 1 per step but can fall by any amount ("abcabcd" falls from 3 to 0). Hold on to this shape: slow climbs and sudden drops. It is the whole reason the algorithm is linear.

08The search loop

We have a rule and a table. For this section, pretend the table is given (we take it from the slow brute-force function of section 5) and concentrate on the search. The warm-up question is: what does the loop have to remember?

Only two numbers. text_index, the position of the text character we are about to look at; it only ever goes up. And matched_count, the number of pattern characters that currently match the text ending just before text_index. The start of the current attempt is never stored: it is text_index - matched_count if you ever want it.

For each text character there are three things that can happen:

  1. It equals pattern[matched_count]. One more character matches: matched_count += 1.
  2. It differs and matched_count > 0. Apply the KMP rule: matched_count = border_length[matched_count - 1], and look at the same text character again.
  3. It differs and matched_count == 0. Nothing to reuse; go to the next text character.

Case 2 can repeat. After falling back to a border of length \(b\), the character pattern[b] may not match either. But then we are in the same situation as before, only with \(b\) matched characters instead of \(k\), and the same reasoning applies: fall back to the longest border of pattern[:b]. That is why the code has a while and not an if.

from borders import border_table_brute_force


def kmp_search(text: str, pattern: str) -> list[int]:
    """Start index of every occurrence of a non-empty pattern in text."""
    border_length = border_table_brute_force(pattern)  # slow for now; section 9 fixes it
    match_starts: list[int] = []
    matched_count = 0  # how many pattern characters match the text ending right here
    for text_index, text_char in enumerate(text):
        while matched_count > 0 and pattern[matched_count] != text_char:
            matched_count = border_length[matched_count - 1]  # slide to the longest border
        if pattern[matched_count] == text_char:
            matched_count += 1
        if matched_count == len(pattern):
            match_starts.append(text_index - len(pattern) + 1)
            matched_count = border_length[matched_count - 1]
    return match_starts

One line needs a comment: what happens after a full match. All \(m\) characters matched, so there is no pattern[m] to compare next. We treat this exactly like a mismatch one step past the end: the matched part is the whole pattern, so we fall back to the longest border of the whole pattern, border_length[m - 1]. This is what finds overlapping occurrences. For "aaa" in "aaaaaa" the border is "aa", two characters stay matched, and the next a completes another occurrence at once.

Problem 8.1 easy

Trace the search for "abab" (table [0, 0, 1, 2]) in "abababab". Give matched_count after each text character, the reported starts, and the number of comparisons.

Solution

Characters 0–3 (a b a b) match one after another: 1, 2, 3, 4. Full match, report start 0, fall back to border_length[3] = 2.

Character 4 is a, compared with pattern[2] = a: 3. Character 5 is b against pattern[3]: 4. Report start 2, fall back to 2.

Characters 6 and 7 repeat that: 3, then 4. Report start 4.

Sequence: 1, 2, 3, 4, 3, 4, 3, 4. Starts [0, 2, 4]. Eight comparisons, one per text character, with no failed comparison at all: the fallbacks after a full match cost no comparison. The naive search needs 14.

Problem 8.2 medium

Trace "mamamia" (table [0, 0, 1, 2, 3, 0, 0]) in "mamamamamia". Where do fallbacks happen and where is the occurrence?

Solution

Characters 0–4 (m a m a m) match: matched_count reaches 5.

Character 5 is a; pattern[5] is i. Mismatch. Fall back: border_length[4] = 3 (the border "mam" of "mamam"). Now pattern[3] is a: match, 4.

Character 6 is m against pattern[4] = m: 5.

Problem 8.3 medium

Find the bug. Someone wrote the fallback inside the while as matched_count = border_length[matched_count]. Describe what happens for (a) pattern "coconut" in text "cococonut", and (b) pattern "aab" in text "ab".

Solution

The index should be matched_count - 1: the matched part has matched_count characters and ends at index matched_count - 1. The buggy line looks up the border of a prefix that is one character too long, including the character that just failed to match.

(a) Table of "coconut": [0, 0, 1, 2, 0, 0, 0]. After coco (count 4) the text has c and the pattern has n. Correct: border_length[3] = 2, keep co, and the occurrence at index 2 is found. Buggy: border_length[4] = 0, everything is thrown away, and the search restarts at text index 4 with nothing matched. From there the text reads conut, which is not the pattern. The result is []: a silently missed occurrence.

(b) Table of "aab": [0, 1, 0]. After the first a the count is 1. Next text character is b, and pattern[1] is a: mismatch. Buggy fallback: border_length[1] = 1. The count is still 1, the same comparison fails again, forever. An infinite loop.

The correct line can never loop: a border is proper, so border_length[k - 1] < k and every fallback strictly decreases the count.

09Building the table fast

The search is now fast, but the table still comes from brute force: for each of \(m\) prefixes it tries up to \(m\) lengths, and each try compares up to \(m\) characters. That is on the order of \(m^3\) steps. We need to do better, and the way to do better is to compute the entries from left to right and let each one help the next.

A longer border is a shorter border plus one character

Suppose we already know everything about the prefix ending at index end_index - 1, and we now add the character pattern[end_index]. What can a border of the new, longer prefix look like?

Say it has length \(L \ge 1\). Its first copy is pattern[:L], and its second copy ends at end_index. Cut the last character off both copies. The remainders, of length \(L - 1\), are still equal, and the second one now ends at end_index - 1. So:

Borders grow one character at a time

Every non-empty border of the prefix ending at end_index is a border of the previous prefix, extended by one character. A border of length \(c\) of the previous prefix can be extended exactly when pattern[c] == pattern[end_index]: the character after its first copy must equal the newly added character.

So to find the longest border of the new prefix, go through the borders of the previous prefix from longest to shortest and take the first one that can be extended. If none can, not even the empty one (which extends when pattern[0] == pattern[end_index]), the answer is 0.

The longest border of the previous prefix is in the table already: border_length[end_index - 1]. But how do we get the second longest, the third longest, without brute force?

Borders of borders

Look at "abracadabra" again. Its borders are "abra" and "a". Now look at the borders of "abra" itself: just "a".

This always works, and the reason fits in one picture.

Borders of borders

The borders of a word are: its longest border B, and then the borders of B. So the full list, longest first, is the chain you get by repeatedly asking "what is the longest border of that?": the lavender arcs of section 7, followed until they reach 0.

Formal proof of both directions

Let the word be \(w\) with length \(n\), let \(B\) be its longest border with length \(b\), and let \(C\) be a string of length \(c < b\).

If \(C\) is a border of \(w\), it is a border of \(B\). \(C = w[0:c]\), and \(B = w[0:b]\) with \(c < b\), so \(C\) is a proper prefix of \(B\). Also \(C = w[n-c:n]\), and \(B = w[n-b:n]\), so \(C\) is the last \(c\) characters of the right copy of \(B\), hence a proper suffix of \(B\) as a string.

If \(C\) is a border of \(B\), it is a border of \(w\). \(C\) is a prefix of \(B\), which is a prefix of \(w\), so \(C\) is a prefix of \(w\). \(C\) is a suffix of \(B\), which is a suffix of \(w\), so \(C\) is a suffix of \(w\). And \(c < b < n\), so it is proper.

Every border of \(w\) other than \(B\) is shorter than \(B\) (because \(B\) is the longest and two borders of the same length are the same string), so the borders of \(w\) are exactly \(B\) together with the borders of \(B\). Apply the same statement to \(B\), then to its longest border, and so on; the lengths strictly decrease, so the chain ends at the empty string after finitely many steps.

Putting the two together

To fill border_length[end_index]:

  1. Start with candidate_length = the longest border of the previous prefix.
  2. While the candidate cannot be extended (pattern[candidate_length] != pattern[end_index]) and is not empty, replace it by the next border in the chain: candidate_length = border_length[candidate_length - 1].
  3. If it can be extended now, add 1.

If that looks familiar, it should. It is the search loop, line for line, with the pattern in the role of the text. Building the table is searching for the pattern inside itself, starting one step to the right so that the pattern is not simply matched against its own beginning.

The complete algorithm, with nothing left to brute force:

def build_border_table(pattern: str) -> list[int]:
    """border_length[end_index] = length of the longest border of pattern[: end_index + 1]."""
    border_length = [0] * len(pattern)
    candidate_length = 0  # longest border of the prefix that ends just before end_index
    for end_index in range(1, len(pattern)):
        while candidate_length > 0 and pattern[candidate_length] != pattern[end_index]:
            candidate_length = border_length[candidate_length - 1]
        if pattern[candidate_length] == pattern[end_index]:
            candidate_length += 1
        border_length[end_index] = candidate_length
    return border_length


def kmp_search(text: str, pattern: str) -> list[int]:

    if not pattern:
        return list(range(len(text) + 1))

        if matched_count == len(pattern):
            match_starts.append(text_index - len(pattern) + 1)
            matched_count = border_length[matched_count - 1]
    return match_starts

Problem 9.3 hard

Prove: if a word has borders of lengths \(b\) and \(c\) with \(c < b\) and \(2c \ge b\), then it also has a border of length \(2c - b\). (Example: borders of lengths 8 and 5 force one of length 2.)

Hint

By "borders of borders", the border of length \(c\) is a border of the border of length \(b\). So think of a word of length \(b\) with a border of length \(c\), and recall Problem 5.2: that word repeats itself every \(b - c\) characters.

Solution

Let \(B\) be the border of length \(b\) and \(C\) the one of length \(c\). By the borders-of-borders fact, \(C\) is a border of \(B\). As in Problem 5.2, a border of length \(c\) in a string of length \(b\) means \(B[i] = B[i + p]\) for every valid \(i\), where \(p = b - c\).

Now ask whether \(C\) has a border of length \(c - p = 2c - b\) (this needs \(2c - b \ge 0\)). \(C\) is the first \(c\) characters of \(B\), so it inherits the repetition: \(C[i] = C[i + p]\) for \(0 \le i < c - p\). Read as a statement about strings, that says the first \(c - p\) characters of \(C\) equal its last \(c - p\) characters: a border of \(C\) of length \(2c - b\).

A border of \(C\) is a border of \(B\), which is a border of the word. Done.

Check on "abcabcabcab", whose borders have lengths 8, 5, 2. With \(b = 8, c = 5\): \(2c - b = 2\). It is there. The border lengths 8, 5, 2 step down by the same amount, 3, which is the period of the word.

10Why it never misses a match

So far the argument has been: dead shifts are skipped, live ones are not. That is convincing for one mismatch. But the loop runs for thousands of characters, with fallbacks stacked on fallbacks. To be sure about the whole run we need a tool for reasoning about loops.

Detour: loop invariants

A way to prove a loop correct without simulating it. Built from scratch here because you marked it as shaky; it takes one small example, and then KMP's correctness is a single sentence.

The idea on a loop you already trust

def largest_price(prices: list[int]) -> int:
    best_price = prices[0]
    for next_index in range(1, len(prices)):
        # Invariant: best_price is the largest of the prices seen so far.
        assert best_price == max(prices[:next_index])
        if prices[next_index] > best_price:
            best_price = prices[next_index]
    return best_price


if __name__ == "__main__":
    print(largest_price([30, 12, 45, 45, 7]))
45

Why does this return the largest price? You could say "it obviously does", but try to say why in a way that would also work for a loop you do not trust. The method is to find a sentence that is true every time the loop is about to start an iteration. Here:

"best_price is the largest of prices[:next_index]."

Such a sentence is called a loop invariant. Proving it takes three small steps, the same three every time:

  1. It is true at the start. Before the first iteration next_index is 1 and best_price is prices[0], the largest of the one-element list prices[:1].
  2. One iteration keeps it true. Assume it holds for next_index. The body compares best_price with prices[next_index] and keeps the larger. The largest of prices[:next_index + 1] is the larger of "the largest of prices[:next_index]" and prices[next_index]. So the sentence holds for next_index + 1.
  3. At the end it says what we want. When the loop finishes, the same sentence holds with next_index = len(prices): best_price is the largest of the whole list.

This is induction, dressed as a loop: step 1 is the base case, step 2 is the induction step. The work is in choosing the sentence. A good invariant describes what the loop's variables mean in terms of the part of the input processed so far. The assert in the code is that sentence, executable.

Problem 10.1 easy

This loop removes duplicates from a sorted list in place and returns how many values remain (LeetCode 26). State an invariant about kept_count that holds before every iteration.

def remove_duplicates(sorted_values: list[int]) -> int:
    kept_count = 0

Solution

"sorted_values[:kept_count] holds the distinct values among the elements read so far, in increasing order, each once."

Start: nothing read, kept_count is 0, the empty list holds the distinct values of nothing. Step: the next value is either equal to the last kept one (because the input is sorted, a repeat can only equal the most recent distinct value), in which case nothing changes and the sentence still holds; or it is new and larger, and it is appended. End: all elements read, so the first kept_count cells hold all distinct values.

A weaker sentence such as "kept_count is at most the number of elements read" is true but useless: the third step would not give the result. The invariant has to be strong enough to imply the goal at the end.

The invariant of the KMP search

What does matched_count mean? Section 8 said: the number of pattern characters that match the text ending here. Sharpen that until it is unambiguous:

Invariant of the search loop

Before the loop reads text[text_index], matched_count is the length of the longest prefix of the pattern, shorter than the whole pattern, that is a suffix of the text read so far, text[:text_index].

The word that carries the weight is longest. A long prefix of the pattern at the end of the text read so far is an occurrence in progress, and the longest one is the occurrence in progress that started earliest. If we always track the earliest-started attempt that is still alive, we cannot have skipped a live one.

Check the sentence against the trace table in section 8. Before index 6 the text read is "cococo" and matched_count is 4. The prefixes of "cocoa" are c, co, coc, coco. Which of them end "cococo"? co and coco. The longest has length 4.

Now the three steps, first in pictures.

Start. Nothing read; the only prefix that is a suffix of the empty text is the empty one; matched_count is 0.

One iteration. We read one more character, text_char. Any pattern prefix that ends the new text consists of a pattern prefix that ended the old text, plus text_char. (Cut the last character off, as in section 9.) So the candidates are: the pattern prefixes that ended the old text, each extended by one.

Which pattern prefixes ended the old text? The longest has length matched_count, by the invariant. Any shorter one is a prefix of the pattern and a suffix of the old text; since the old text ends with pattern[:matched_count], it is a prefix and a suffix of pattern[:matched_count]: a border of it. So the full list of candidates, longest first, is matched_count followed by the border chain. The while loop walks exactly that list and stops at the first candidate whose next pattern character equals text_char. First in a longest-first list means longest. The invariant holds again.

What it gives us. An occurrence ending at text_index means the whole pattern is a suffix of the text read so far. After the if, matched_count is the longest pattern prefix ending there, so it equals \(m\) exactly when an occurrence ends there. Nothing is missed and nothing false is reported. After reporting, the code falls back to the longest border of the whole pattern, which is the longest prefix shorter than the pattern ending there, and the sentence is true again for the next round.

Formal proof

Notation: \(T_i\) is text[:i], \(P_k\) is pattern[:k], \(m\) is len(pattern), and \(\pi(k)\) is the length of the longest border of \(P_k\), which is border_length[k - 1]. Define

\[ F(i) = \max\{\,k \le m : P_k \text{ is a suffix of } T_i\,\}, \qquad G(i) = \max\{\,k < m : P_k \text{ is a suffix of } T_i\,\}. \]

Claim. At the top of the iteration for index \(i\), matched_count \(= G(i)\). After the while and the if, matched_count \(= F(i+1)\).

Base. \(G(0) = 0\) because \(T_0\) is empty.

Step. Assume matched_count \(= g = G(i)\). Let \(S = \{k < m : P_k \text{ suffix of } T_i\}\).

(1) \(S = \{g, \pi(g), \pi(\pi(g)), \dots, 0\}\). Indeed \(g \in S\) is its maximum. For \(k < g\): \(P_k\) is a prefix of \(P_g\) (both are prefixes of the pattern), and \(P_k\) is a suffix of \(T_i\) if and only if it is a suffix of \(P_g\) (because \(T_i\) ends with \(P_g\) and \(k < g\)). So \(k \in S\) exactly when \(P_k\) is a border of \(P_g\), and by the borders-of-borders lemma those are \(\pi(g), \pi(\pi(g)), \dots, 0\).

(2) For \(k' \ge 1\): \(P_{k'}\) is a suffix of \(T_{i+1}\) if and only if \(P_{k'-1}\) is a suffix of \(T_i\) and pattern[k'-1] == text[i]. Since \(k' \le m\), we have \(k' - 1 < m\), so the condition is \(k'-1 \in S\) and pattern[k'-1] == text[i].

(3) The while loop visits the elements of \(S\) in decreasing order and stops at the first \(k\) with pattern[k] == text[i], or at 0. If it stops at a \(k\) with equality, the if makes matched_count \(= k + 1\), the largest \(k'\) satisfying (2). If it reaches 0 without equality, no \(k' \ge 1\) satisfies (2), and matched_count stays 0. In both cases matched_count \(= F(i+1)\).

(4) If \(F(i+1) = m\), an occurrence ends at \(i\) and is reported; the proper prefixes that are suffixes of \(T_{i+1}\) are then the borders of the pattern, so \(G(i+1) = \pi(m)\), which is what the code assigns. If \(F(i+1) < m\), no occurrence ends at \(i\), and \(G(i+1) = F(i+1)\). Either way the claim holds for \(i + 1\). ∎

The same proof, with the pattern read in place of the text and the loop started at 1, shows that build_border_table is correct: its invariant is "candidate_length is the longest border of pattern[:end_index]".

11Why it is linear

The search has a while inside a for. The for runs \(n\) times, and one run of the while can fall back many times: with the pattern "aaaab", after matching aaaa a text character c causes four fallbacks in a row (4 → 3 → 2 → 1 → 0). The reflex estimate is "\(n\) iterations times up to \(m\) fallbacks, so \(O(nm)\)", no better than the naive search. The reflex is wrong, and seeing why needs one more tool.

Detour: amortized analysis

How to bound the total cost of a loop whose individual iterations vary wildly. You marked it as shaky, and you have almost certainly used it without the name: it is the reason a monotonic stack is linear.

The idea on a loop you already trust

def days_until_warmer(temperatures: list[int]) -> tuple[list[int], int]:
    """For each day, how many days until a warmer one (0 if never). Also returns the pop count."""
    waits = [0] * len(temperatures)
    waiting_days: list[int] = []  # indexes of days still waiting, temperatures decreasing
    pop_count = 0
    for today, temperature in enumerate(temperatures):
        while waiting_days and temperatures[waiting_days[-1]] < temperature:
            earlier_day = waiting_days.pop()
            pop_count += 1
            waits[earlier_day] = today - earlier_day
        waiting_days.append(today)
    return waits, pop_count

This is the "daily temperatures" problem. It also has a while inside a for, and in the second example the last day pops seven entries in one go. Yet nobody calls it quadratic, and the argument is short: every day is pushed exactly once, and a day can only be popped after it was pushed. So over the whole run, the number of pops is at most the number of pushes, which is \(n\). Some iterations are expensive, but an expensive iteration is only possible because earlier iterations were cheap and left things on the stack.

That is amortized analysis: do not bound each iteration by its worst case and multiply. Instead, find a quantity that every expensive operation uses up and that can only be built up slowly, and bound the total. The general recipe:

  1. Pick a non-negative quantity (here: the stack height).
  2. Show it rises by at most a fixed amount per outer iteration (here: one push).
  3. Show every inner-loop step lowers it by at least 1 (here: one pop).
  4. Conclude: total inner steps ≤ total rise ≤ number of outer iterations.

The same argument for KMP

The quantity is matched_count.

  • It is never negative.
  • It rises by at most 1 per text character: the if adds 1, at most once per iteration.
  • Every fallback lowers it by at least 1, because a border is proper: border_length[k - 1] < k.

So the total number of fallbacks over the whole search is at most the total rise, which is at most \(n\). A burst of four fallbacks is only possible after four successful matches built the height up.

Counting comparisons exactly

Count each comparison of a text character with a pattern character once. (In the code the while condition and the if can test the same pair twice; that is one comparison written two times.) Every comparison has one of three outcomes:

  • Success. It ends the iteration. Call the total \(S\).
  • Failure with matched_count == 0. It also ends the iteration. Call the total \(Z\).
  • Failure followed by a fallback. Call the total \(F\).

Every iteration ends in exactly one of the first two ways, so \(S + Z = n\). Each success raises matched_count by 1 and each fallback lowers it by at least 1, so \(F \le S \le n\). Therefore

\[ \text{comparisons} = S + Z + F = n + F \le 2n. \]

The same count for build_border_table, which is the same loop over the pattern, gives at most \(2m\). Altogether:

Cost

Time \(O(n + m)\): at most \(2m\) comparisons to build the table and at most \(2n\) to search. Extra space \(O(m)\) for the table. The text is read strictly left to right, one character at a time, so it can be a stream.

Problem 11.3 medium

The naive search on "aaaa…ab" also has "cheap" and "expensive" starts. Why can the amortized recipe not be used to prove it linear? Which step of the recipe fails?

Solution

Take the same quantity, the number of matched characters. In the naive search, a mismatch resets it to 0 and moves the text position back by matched_count - 1. The quantity then rises again by re-reading the same text characters. So "it rises at most once per text character" is false: step 2 of the recipe fails, because there is no fixed supply of rises. The same character can pay for a rise up to \(m\) times.

KMP's rises are tied to text characters that are consumed for good, which is where the bound \(S \le n\) comes from. Never moving back in the text is the property that makes the accounting work.

Problem 12.1 medium

Trace the if-instead-of-while bug on pattern "bbb" (table [0, 1, 2]) and text "bbabb", and say exactly which state is wrong.

Solution

After bb: matched_count = 2. Next character a: pattern[2] = b differs, fall back once to border_length[1] = 1. The correct code would test again, find pattern[1] = b differs from a, fall back to 0, find pattern[0] differs too, and end with 0.

The buggy code falls back only once. Its if then tests pattern[1] == "a", which is false, so matched_count stays 1. That state claims "the text read so far ends with b", but it ends with a. The invariant is broken.

The remaining bb then lifts the count from 1 to 3, and an occurrence is reported at index 4 − 3 + 1 = 2, where the text reads abb.

13What else the table is good for

In contest problems and on LeetCode the search is the less common use of KMP. The border table on its own answers a surprising number of questions about a single string. All of the functions below are in one file, shown and run at the end of the section.

All borders, not only the longest

By the borders-of-borders fact, following the chain from the last entry lists every border length of the whole word, longest first. For "abracadabra": 4, then 1. This is LeetCode 1392 ("Longest Happy Prefix") if you stop at the first step.

The shortest period

A period of a word is a distance \(p \ge 1\) such that the word looks the same when moved \(p\) steps to the right: word[i] == word[i + p] wherever both indexes exist. "alfalfa" has period 3: it is alf repeated, cut off after the seventh letter.

The picture is the demo of section 6 again, and the conclusion is the same: the word agrees with itself moved by \(p\) exactly when its first \(n - p\) characters equal its last \(n - p\) characters.

Periods are borders

A word of length \(n\) has period \(p\) if and only if it has a border of length \(n - p\). The longest border gives the shortest period: \(p_{\min} = n - \) border_length[n - 1].

Is the word a block repeated a whole number of times?

LeetCode 459 asks whether a word is some shorter block written two or more times, like "abcabcabc". With the shortest period \(p\) in hand, the answer is: yes exactly when \(p < n\) and \(p\) divides \(n\).

One direction is direct. If \(p\) divides \(n\), then word[i] == word[i + p] for all \(i\) says each block of \(p\) characters equals the next, and the blocks tile the word exactly. The other direction, that a word which is some block repeated must have its shortest period dividing \(n\), needs a classical result, the Fine–Wilf theorem (1965): if a word has periods \(p\) and \(q\) and length at least \(p + q - \gcd(p, q)\), it also has period \(\gcd(p, q)\). If the word is a block of length \(q\) repeated at least twice, then \(q \le n/2\) and \(p \le q\), so \(p + q \le n\) and \(\gcd(p, q)\) is a period. But \(p\) is the smallest period, so \(\gcd(p, q) = p\), meaning \(p\) divides \(q\), which divides \(n\).

Search with nothing but the table

Glue the pattern, a separator character that occurs in neither string, and the text together: pattern + "#" + text. Build the border table of the whole thing. No border can cross the separator, so no entry exceeds \(m\). An entry in the text part equals \(m\) exactly where the first \(m\) characters of the glued string, the pattern, end at that position. This is a full pattern search with one function and no separate search loop, at the price of \(O(n + m)\) memory instead of \(O(m)\).

The shortest palindrome by adding letters in front

LeetCode 214. To turn word into a palindrome by prepending as few letters as possible, find its longest prefix that is already a palindrome; the rest, reversed, goes in front. A prefix of word is a palindrome exactly when it equals a suffix of the reversed word. So build the table of word + "#" + reversed_word: its last entry is the longest prefix of word that is a suffix of the reversal.

How often does each prefix occur?

For every length, count the occurrences of word[:length] inside word. Entry border_length[end_index] says the longest prefix ending at end_index; the shorter prefixes ending there are its borders. So count each entry once, then push the counts down the chain from long to short, and finally add one for each prefix's own occurrence at the start.

from kmp import build_border_table


def all_border_lengths(word: str) -> list[int]:
    """Every border length of word, longest first, by walking the border chain."""
    border_length = build_border_table(word)
    lengths: list[int] = []
    length = border_length[-1] if word else 0
    while length > 0:
        lengths.append(length)
        length = border_length[length - 1]
    return lengths


def shortest_period(word: str) -> int:
    """Smallest p > 0 with word[i] == word[i + p] wherever both indices exist."""
    return len(word) - build_border_table(word)[-1]


def is_repeated_block(word: str) -> bool:
    """True if word is some shorter block written two or more times (LeetCode 459)."""
    period = shortest_period(word)
    return period < len(word) and len(word) % period == 0


def shortest_palindrome(word: str) -> str:
    """Shortest palindrome obtainable by adding characters in front of word (LeetCode 214)."""
    if not word:
        return word
    reversed_word = word[::-1]
    palindromic_prefix_length = build_border_table(word + "#" + reversed_word)[-1]
    return reversed_word[: len(word) - palindromic_prefix_length] + word


def search_by_concatenation(text: str, pattern: str) -> list[int]:
    """Pattern search using nothing but the border table of pattern + '#' + text."""
    border_length = build_border_table(pattern + "#" + text)
    return [
        joined_index - 2 * len(pattern)
        for joined_index in range(len(pattern) + 1, len(border_length))
        if border_length[joined_index] == len(pattern)
    ]


def prefix_occurrence_counts(word: str) -> list[int]:
    """counts[length] = how many times word[:length] occurs in word as a substring."""
    border_length = build_border_table(word)
    counts = [0] * (len(word) + 1)
    for length in border_length:
        counts[length] += 1
    for length in range(len(word), 0, -1):
        counts[border_length[length - 1]] += counts[length]
    for length in range(1, len(word) + 1):
        counts[length] += 1  # the prefix itself, sitting at the start
    return counts

Problem 13.1 easy

The table of "abaabaab" is [0, 0, 1, 1, 2, 3, 4, 5]. Give its shortest period, say whether it is a repeated block, and list all its borders.

Solution

\(n = 8\), last entry 5, so the shortest period is \(8 - 5 = 3\) (the block aba).

3 does not divide 8, so it is not a whole number of repetitions: it is aba aba ab, two and two-thirds blocks.

Borders: follow the chain. Length 5 (abaab). Then border_length[4] = 2 (ab). Then border_length[1] = 0. Borders: abaab and ab. The lengths 5 and 2 differ by the period, 3, as in Problem 9.3.

Problem 13.2 medium

In the concatenation trick, drop the separator and build the table of pattern + text for pattern "aa" and text "aaa". What goes wrong, and does "report where the entry is ≥ \(m\)" fix it?

Solution

The table of "aaaaa" is [0, 1, 2, 3, 4]. With the separator, the table of "aa#aaa" is [0, 1, 0, 1, 2, 2], and the entries equal to 2 in the text part mark the occurrences ending at text indexes 1 and 2.

Without it, borders run across the join and entries grow past \(m\): they describe prefixes of the glued string that include text characters, which is not what we are asking about. Testing "≥ \(m\)" does not repair this in general. An entry \(\ge m\) says that some prefix of pattern + text of that length ends here, and so the pattern does start that prefix, but the prefix may begin inside the pattern part of the glued string, so the reported text position can be wrong or negative. In this example entry 2 at glued index 2 would be reported as an occurrence ending at text index 0, which is impossible for a pattern of length 2.

The separator is what guarantees every border lies entirely inside the pattern. If no safe separator character exists (arbitrary bytes), run the real search loop instead; it needs none.

Problem 13.3 medium

LeetCode 796: decide whether goal is a rotation of word (for example "cdeab" is a rotation of "abcde"). Reduce it to one pattern search and state the complexity.

Solution

If the lengths differ, the answer is no. Otherwise, every rotation of word appears as a substring of word + word, and every substring of word + word of length len(word) is a rotation. So the answer is whether kmp_search(word + word, goal) is non-empty. For the example, "cdeab" occurs in "abcdeabcde" at index 2.

Time and space \(O(n)\), against \(O(n^2)\) for trying all rotations. The length check is not optional: without it "ab" would count as a rotation of "abc".

14Summary

  1. A successful comparison is knowledge about the text. After \(k\) matched characters, the last \(k\) text characters are pattern[:k]. Everything the naive search re-reads is already determined by the pattern.
  2. Shifts are borders. Sliding the pattern by \(s\) can work only if pattern[:k] has a border of length \(k - s\). Take the longest border: it is the smallest shift that is not provably dead, and its characters need no re-comparison.
  3. Borders of borders. All borders of a string are its longest border, that border's longest border, and so on. This is what lets the fallback repeat, and what lets the table be built by running the same loop on the pattern itself.
  4. The invariant. matched_count is always the longest proper pattern prefix that ends the text read so far. An occurrence ends here exactly when it reaches \(m\).
  5. The accounting. matched_count rises at most once per character and every fallback lowers it, so fallbacks total at most \(n\) and comparisons at most \(2n\). Time \(O(n + m)\), space \(O(m)\), and the text is never re-read.
The lines to remember

Fallback, in both loops: count = border_length[count - 1], inside a while count > 0 and mismatch.
Table loop starts at index 1; search loop starts at index 0.
After a full match: record text_index - m + 1, then fall back once more.
Shortest period: n - border_length[n - 1].

15Quiz

A mixed review of the whole page. Answer from memory first.

Q1 easy

Write the border table of "aabaa".

Solution

a → 0. aa → 1. aab → 0. aaba → 1 (a). aabaa → 2 (aa). Table [0, 1, 0, 1, 2].

Q2 easy

The pattern begins "abcabca…". After matching those seven characters, the eighth mismatches. What is the new matched_count, and how far does the pattern slide?

Solution

The longest border of "abcabca" is "abca" (first four = last four, overlapping in the middle a). New count 4, slide \(7 - 4 = 3\). The frequent wrong answer is 1 (the border "a"), from not considering overlapping borders.

Q3 easy

True or false: border_length[i] can be larger than i.

Solution

False. The prefix ending at i has \(i + 1\) characters and a border is proper, so its length is at most \(i\). The table of "aaaa", [0, 1, 2, 3], reaches that maximum everywhere.

Q4 easy

Which of these cannot be the border table of any string: [0, 0, 1, 2, 3], [0, 1, 0, 2], [0, 0, 0, 0]?

Solution

[0, 1, 0, 2] is impossible: an entry can exceed the previous one by at most 1 (Problem 7.2), and here it jumps from 0 to 2. The first is the table of "ababa", the last of "abcd".

Q5 medium

Describe all strings whose border table is entirely zeros.

Solution

Exactly the strings whose first character never appears again. If the first character reappears at index \(i > 0\), the prefix ending at \(i\) starts and ends with that character, so it has a border of length at least 1. If it never reappears, no prefix can have a non-empty border, because any non-empty border starts with the first character and would need a second copy of it later.

So "abcd" and "abbb" both give [0, 0, 0, 0]: the table does not determine the string.

Q6 medium

A text of 1,000,000 characters and a pattern of 1,000. Give an upper bound on the character comparisons KMP makes in total, and the corresponding worst case of the naive search.

Solution

KMP: at most \(2m = 2{,}000\) for the table plus \(2n = 2{,}000{,}000\) for the search: 2,002,000.

Naive: \((n - m + 1)\cdot m = 999{,}001 \times 1{,}000 = 999{,}001{,}000\), about five hundred times more.

Q7 medium

The pattern is "cocoa" and the text read so far is "xcococ". Using only the invariant, what is matched_count?

Solution

The longest proper prefix of "cocoa" that ends "xcococ". Candidates: coco (text ends …ococ, no), coc (text ends …coc, yes). So 3.

Q8 medium

The table of a 12-character string ends in 8. What is the shortest period? Is the string a repeated block? What other border lengths must it have?

Solution

Shortest period \(12 - 8 = 4\). Since 4 divides 12 and \(4 < 12\), the string is a 4-character block written three times.

A string with period 4 and length 12 also agrees with itself moved by 8, so it has a border of length \(12 - 8 = 4\): the block itself. Below that, the chain continues with the borders of the block: none for a block like abcd, one more for abca. So 8 and 4 for certain, and possibly shorter ones.

Q9 hard

Explain in two sentences, to someone who knows the code but not the theory, why the inner while does not make KMP quadratic.

Solution

Each pass through the while lowers matched_count by at least one, and matched_count is raised only by the if, at most once per text character, and never goes below zero. So over the entire run the while body executes at most as many times as the if succeeds, which is at most \(n\).

17Extensions: KMP as a machine

Detour: finite automata

You marked automata as shaky. They are not needed for anything above, but the automaton is the most compact way to think about what KMP is, and it is the form in which the idea generalises. Here is the minimum, from nothing.

A deterministic finite automaton (DFA) is a machine with a finite set of states, one of which is the start state. It reads its input one character at a time. A fixed table, the transition function, says for every state and every character which state comes next. Some states are marked accepting. That is the whole definition: no memory except "which state am I in", no going back, one table lookup per character.

The diagrams of section 7 were almost automata. The nodes are states: state \(k\) means "matched_count is \(k\)". The yellow arrows are transitions. What was missing is that a DFA must have an answer for every character in every state, without an inner loop. The lavender arcs were not transitions; they were instructions to "go there and try again".

We can remove the "try again" by doing it ahead of time. For each state \(k\) and each character, run the fallback loop once, in advance, and write down where it ends:

  • if the character is pattern[k], go to \(k + 1\);
  • otherwise, if \(k = 0\), stay at 0;
  • otherwise, do whatever the state border_length[k - 1] does on that character. That state is smaller, so its row is already filled in.
from kmp import build_border_table


def build_automaton(pattern: str, alphabet: str) -> list[dict[str, int]]:
    """next_state[matched_count][char] = matched_count after reading char."""
    border_length = build_border_table(pattern)
    next_state: list[dict[str, int]] = []
    for matched_count in range(len(pattern) + 1):
        row: dict[str, int] = {}
        for char in alphabet:
            if matched_count < len(pattern) and pattern[matched_count] == char:
                row[char] = matched_count + 1
            elif matched_count == 0:
                row[char] = 0
            else:
                row[char] = next_state[border_length[matched_count - 1]][char]
        next_state.append(row)
    return next_state


def automaton_search(text: str, pattern: str, alphabet: str) -> list[int]:
    next_state = build_automaton(pattern, alphabet)
    match_starts: list[int] = []
    state = 0
    for text_index, text_char in enumerate(text):
        state = next_state[state][text_char]
        if state == len(pattern):
            match_starts.append(text_index - len(pattern) + 1)
    return match_starts

The search is then a single lookup per character, with no inner loop at all. The price is the table: one entry per state per character of the alphabet, \(O(m \cdot |\Sigma|)\) time and space, against \(O(m)\) for the border table. For bytes that is 256 entries per state; for Unicode it is out of the question, which is why the border-table form is the usual one.

Knuth's refinement

Strictly speaking, what this page has built is the algorithm of Morris and Pratt. Knuth's contribution to the published version includes a sharper table. Look at "cocoa" in state 3 (coc matched, next expected character o). On a mismatch we fall back to state 1, which expects pattern[1]: also o. But we just learned that the text character is not o. That fallback is certain to fail again.

The refinement: when pattern[border] equals pattern[k], skip that border and link directly to wherever it would fall back. This "strong" failure function does not change the \(O(n + m)\) total, but it bounds the worst delay at a single text character: Knuth, Morris and Pratt show that the number of consecutive fallbacks is then at most about \(\log_\varphi m\), where \(\varphi\) is the golden ratio, instead of up to \(m\). Homework 5 asks you to see that bound on Fibonacci strings, which are the worst case.

Where the idea goes next

  • Aho–Corasick (1975) searches for many patterns at once. The chain of states becomes a trie, and each node gets a failure link defined the same way. It is what fgrep was built on.
  • Counting and DP over strings. "How many strings of length \(n\) avoid a given substring?" becomes a walk on the automaton's states; LeetCode 1397 is this.
  • Sequences that are not text. Nothing above used anything about characters except equality. KMP works on lists of integers, tokens, or the differences between neighbouring array elements (LeetCode 3036).

18Alternatives

KMP was the first widely known linear-time matcher, and it is rarely the fastest in practice. A brief map, since you asked to keep this out of scope:

MethodIdeaWhen it wins
Naive, with a fast first-character scanUse a vectorised memchr to jump to candidatesShort patterns in ordinary text; hard to beat, quadratic only on adversarial input

KMP keeps its place for three reasons: the guarantee is unconditional, it works on a stream without a buffer, and the border table answers structural questions (periods, borders, repetitions) that the faster matchers do not.

19History

The algorithm was found more than once. James H. Morris needed a search for a text editor he was writing on a CDC 6400 around 1970 and wanted to avoid backing up in the input; he and Vaughan Pratt wrote it up in a 1970 Berkeley technical report, A linear pattern-matching algorithm. Independently, Donald Knuth arrived at the same method from theory: Stephen Cook had proved that any language recognisable by a two-way deterministic pushdown automaton can be recognised in linear time on an ordinary computer, which implied that a linear-time pattern matcher had to exist. Knuth worked through Cook's construction for this particular problem and extracted the algorithm; Pratt then showed how to make its running time independent of the alphabet size, and learned that Morris already had the method.

The three published together: Fast Pattern Matching in Strings, SIAM Journal on Computing 6(2), June 1977. The paper is unusually candid about this history, and also contains an early analysis of the then-new Boyer–Moore algorithm.

A similar linear-time method had been found even earlier, in 1969, by Yuri Matiyasevich in the Soviet Union, formulated for a Turing machine with a two-dimensional tape and a binary alphabet.
