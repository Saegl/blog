1. Motivation: a signature split across two packets

Imagine you are writing a small intrusion-detection filter. It sits on a network link and watches HTTP requests go by, and its job is to raise an alarm whenever the bytes ' OR '1'='1 appear. That string is the classic SQL-injection probe. The data does not arrive as one neat string, though. It arrives in packets, and an attacker can, deliberately or not, split the signature across packet boundaries:

packetbytes
1GET /login?user=admin
2' OR '1
3'='1 HTTP/1.1

No single packet contains the signature, but the stream does. You could buffer the whole stream and then call in on it, but on a busy link that buffer is unbounded. What you really want is a matcher that reads every byte exactly once, left to right, never needs to look at an earlier byte again, and carries only a tiny amount of state from one packet to the next. Then you can process packet 2, throw it away, and still notice the match when packet 3 completes it.

The obvious algorithm, “try every starting position and compare”, does not have this property. When a partial match fails, it goes back to the text and re-reads characters it has already seen. The Knuth–Morris–Pratt algorithm (KMP) does have it. By the end of this page you'll have written this exact filter, and between packets it remembers nothing but one integer:

stream_matcher.py
from dataclasses import dataclass, field


def prefix_function(pattern: str) -> list[int]:
    longest_border = [0] * len(pattern)
    for end in range(1, len(pattern)):
        candidate = longest_border[end - 1]
        while candidate > 0 and pattern[end] != pattern[candidate]:
            candidate = longest_border[candidate - 1]
        if pattern[end] == pattern[candidate]:
            candidate += 1
        longest_border[end] = candidate
    return longest_border


@dataclass
class StreamMatcher:
    """Finds a signature in a stream that arrives in chunks. Never stores old chunks."""
    signature: str
    longest_border: list[int] = field(init=False)
    matched: int = 0           # the whole state that survives between chunks
    consumed: int = 0          # characters seen so far, only used to report positions

    def __post_init__(self) -> None:
        self.longest_border = prefix_function(self.signature)

    def feed(self, chunk: str) -> list[int]:
        hits: list[int] = []
        for char in chunk:
            while self.matched > 0 and char != self.signature[self.matched]:
                self.matched = self.longest_border[self.matched - 1]
            if char == self.signature[self.matched]:
                self.matched += 1
            self.consumed += 1
            if self.matched == len(self.signature):
                hits.append(self.consumed - len(self.signature))
                self.matched = self.longest_border[self.matched - 1]
        return hits


detector = StreamMatcher("' OR '1'='1")
packets = ["GET /login?user=admin", "' OR '1", "'='1 HTTP/1.1"]
for packet in packets:
    print(f"{packet!r:24} matched={detector.matched:2}  hits={detector.feed(packet)}  "
          f"-> matched={detector.matched}")
output
'GET /login?user=admin'  matched= 0  hits=[]  -> matched=0
"' OR '1"                matched= 0  hits=[]  -> matched=7
"'='1 HTTP/1.1"          matched= 7  hits=[21]  -> matched=0

Look at the matched column. After packet 2 the matcher's whole memory of the past is the number 7: “the last 7 characters I saw are the first 7 characters of the signature”. That one number is enough to finish the job when packet 3 arrives. Making that number trustworthy, and updating it in amortized constant time per character, is all of KMP.

The same need comes up far from security. A text editor's “find” runs over a gap buffer or a rope rather than a contiguous string. A genome scanner reads gigabytes of ACGT from disk. A log tailer follows a file that keeps growing. A parser looks for a multi-byte delimiter in a socket. Anywhere data streams by and backing up is expensive or impossible, “never look back” is the property you want, and KMP gives it to you with a worst-case guarantee of \(O(n + m)\) time, where \(n\) is the length of the text and \(m\) the length of the pattern.

2. Primer: prefixes, suffixes and borders

KMP's key structure is a table of “borders”. Before we can talk about them we need to agree on how to name pieces of a string, and we need to be painfully careful about indices, because almost every KMP bug is an off-by-one.

Naming pieces of a string

Throughout this page, strings are 0-indexed and sliced the Python way. For a string word of length \(L\) (that is, \(L\) is len(word)):

  • word[a:b] is the characters at indices \(a, a+1, \dots, b-1\). Its length is \(b - a\). The end index is excluded.
  • The prefix of length \(k\) is word[:k], the first \(k\) characters, \(0 \le k \le L\).
  • The suffix of length \(k\) is word[L-k:], the last \(k\) characters, \(0 \le k \le L\).
  • A prefix or suffix is proper if it is not the whole word, that is, if \(k < L\).
  • The empty string "" (length 0) is both a prefix and a suffix of every string.
Trap: word[-k:] It is tempting to write the suffix of length \(k\) as word[-k:]. That is right for \(k \ge 1\), but for \(k = 0\) it gives word[-0:], which is word[0:], the whole word, not the empty string. Since KMP constantly deals with borders of length 0, always write word[len(word) - k:].

Borders

Definition: border A border of a string \(w\) is a string that is both a proper prefix and a proper suffix of \(w\). Equivalently, an integer \(k\) with \(0 \le k < |w|\) is a border length of \(w\) if w[:k] == w[len(w)-k:]. Here \(|w|\) is the length of \(w\).

Every non-empty string has at least one border, the empty one. The interesting question is which longer borders it has. Take "abacaba", the word you get by writing a, then the previous word, then b, and so on. Check every length \(k\) from 0 to 6:

\(k\)prefix w[:k]suffix w[7-k:]border?
0""""yes
1"a""a"yes
2"ab""ba"no
3"aba""aba"yes
4"abac""caba"no
5"abaca""acaba"no
6"abacab""bacaba"no

Two details matter later. First, the whole word (\(k = 7\)) is excluded on purpose. Every word trivially matches itself, and that “border” would tell us nothing. Second, borders are allowed to overlap. In "aaaa" the longest border is "aaa": the prefix uses indices 0–2 and the suffix uses indices 1–3, and they share the middle.

The definition turns directly into a brute-force function. It is far too slow for real use, \(O(L^2)\) per word, but it is the ground truth we'll test everything else against:

borders.py
def borders(word: str) -> list[str]:
    """All proper borders of `word`, shortest first (the empty string included)."""
    return [
        word[:length]
        for length in range(len(word))
        if word[:length] == word[len(word) - length:]
    ]


def shortest_period(word: str) -> int:
    """Smallest p > 0 with word[i] == word[i + p] for every valid i."""
    for period in range(1, len(word) + 1):
        if all(word[i] == word[i + period] for i in range(len(word) - period)):
            return period
    return len(word)


for word in ["abacaba", "aaaa", "abcd", "abcabcab"]:
    longest = borders(word)[-1]
    print(f"{word!r:11} borders={borders(word)!s:22} "
          f"len(word) - len(longest)={len(word) - len(longest)}  period={shortest_period(word)}")

Borders are periods in disguise

Definition: period An integer \(p\) with \(1 \le p \le |w|\) is a period of \(w\) if w[i] == w[i + p] for every \(i\) with \(0 \le i < |w| - p\). In words, the string repeats itself with step \(p\): "abcabcab" has period 3, because each character equals the one three to its right. The length \(|w|\) itself is always a (trivial) period, because the condition then constrains nothing.
Fact: border ↔ period \(w\) has a border of length \(k\) if and only if \(w\) has period \(|w| - k\). So the longest border corresponds to the shortest period: \[ \text{shortest period}(w) = |w| - \text{longest border length}(w). \]

Proof, one step at a time. Write \(L = |w|\) and \(p = L - k\).

  1. “\(k\) is a border length” means w[:k] == w[L-k:], that is, w[:L-p] == w[p:].
  2. Two strings of the same length are equal exactly when they agree at every position. Position \(i\) of w[:L-p] is w[i], and position \(i\) of w[p:] is w[p+i], for \(0 \le i < L - p\).
  3. So the statement in step 1 is the same as “w[i] == w[i+p] for all \(0 \le i < L-p\)”, which is word for word the definition of period \(p\).

The picture: slide a copy of the word \(p\) steps to the right. The overlapping part is a suffix of the top copy lying exactly on a prefix of the bottom copy, and the copies agree there exactly when that suffix equals that prefix.

Hold on to this picture of a string sliding over a copy of itself. It is exactly what KMP does when a match fails.

Border explorer

Try aaaaaa, abcabcabc, abcd, aabaabaa in the explorer. Notice two things. Strings with lots of repetition have lots of borders. And the shorter borders always seem to sit inside the longer ones. That second observation will become the central lemma of KMP.

medium Find the shortest period of "aabaaab" and of "abcabcab" using borders, and double-check one of them against the definition of period.

Solution

"aabaaab" (length 7): the proper borders are "" and "aab" (check: w[:3] = "aab", w[4:] = "aab"; lengths 1, 2, 4, 5, 6 fail). The longest border has length 3, so the shortest period is \(7 - 3 = 4\). Check: w[0..2] = "aab" must equal w[4..6] = "aab" ✓.

"abcabcab" (length 8): borders "", "ab", "abcab", so the shortest period is \(8 - 5 = 3\). Note that 3 does not divide 8. A period does not have to divide the length. The last “repetition” is simply cut short.

medium Prove: if \(u\) is a border of \(w\), and \(v\) is a border of \(u\), then \(v\) is a border of \(w\). (“A border of a border is a border.”)

Solution

Three things to check: \(v\) is a prefix of \(w\), \(v\) is a suffix of \(w\), and \(v\) is proper.

  1. Prefix. \(v\) is a prefix of \(u\), so \(v\) = the first \(|v|\) characters of \(u\). \(u\) is a prefix of \(w\), so the first \(|u|\) characters of \(w\) are \(u\). Since \(|v| < |u|\), the first \(|v|\) characters of \(w\) are the first \(|v|\) characters of \(u\), which are \(v\).
  2. Suffix. The same argument mirrored: the last \(|v|\) characters of \(w\) are the last \(|v|\) characters of its suffix \(u\), which are \(v\).
  3. Proper. \(|v| < |u| < |w|\).

This is the easy half of the “border chain” lemma we'll need later. The harder half says the converse: every border of \(w\) that is shorter than \(u\) (the longest one) is a border of \(u\).

3. Primer: loop invariants (and induction)

KMP's main loop is short, but it is subtle. It keeps one integer, matched, and the whole algorithm is correct only because that integer always means something precise. The tool for saying “always” precisely is the loop invariant.

Definition: loop invariant A loop invariant is a statement about the program's variables that is true every time execution reaches a fixed point in the loop, usually the top of the loop body. Proving one takes three steps:
  1. Initialization. It holds the first time we reach that point.
  2. Maintenance. If it holds at the top of one iteration, it holds at the top of the next.
  3. Termination. When the loop exits, the invariant, combined with the exit condition, gives the result we want.
Detour: why this is just induction Mathematical induction proves “\(P(t)\) for all \(t \ge 0\)” from two pieces: a base case \(P(0)\) and a step “\(P(t) \Rightarrow P(t+1)\)”. The two pieces chain: \(P(0)\) gives \(P(1)\), which gives \(P(2)\), and so on forever. Let \(P(t)\) be “the invariant holds after \(t\) iterations”. Then initialization is the base case and maintenance is the step, so the invariant holds after any number of iterations, in particular after the last one. You don't need to set up induction formally each time. Checking “initialization + maintenance” is the induction.

Here is the standard example, a binary search that returns the first index whose value is at least a budget. I've put the invariant into the code as asserts, which is a great habit for subtle loops (remove them later, since they make the loop linear):

invariants.py
def first_at_least(sorted_prices: list[int], budget: int) -> int:
    """Index of the first price >= budget, or len(sorted_prices) if there is none."""
    low, high = 0, len(sorted_prices)
    while low < high:
        # Invariant: everything left of `low` is < budget,
        #            everything at or right of `high` is >= budget.
        assert all(price < budget for price in sorted_prices[:low])
        assert all(price >= budget for price in sorted_prices[high:])
        middle = (low + high) // 2
        if sorted_prices[middle] < budget:
            low = middle + 1
        else:
            high = middle
    # low == high, so the invariant splits the whole list into "< budget" and ">= budget".
    return low


prices = [3, 5, 5, 8, 13, 21]
for budget in [1, 5, 9, 21, 100]:
    print(f"budget={budget:3} -> index {first_at_least(prices, budget)}")
output
budget=  1 -> index 0
budget=  5 -> index 1
budget=  9 -> index 4
budget= 21 -> index 5
budget=100 -> index 6

The invariant is: everything left of low is < budget, and everything from high on is ≥ budget. Let's walk the three steps.

  1. Initialization. low = 0, so “everything left of index 0” is nothing, and the claim about nothing is vacuously true. high = len, so “everything from index len on” is also nothing. ✓
  2. Maintenance. Suppose it holds and low < high. Pick middle with low ≤ middle < high.
    • If sorted_prices[middle] < budget: the list is sorted, so every price at an index ≤ middle is also < budget. Setting low = middle + 1 keeps “everything left of low is < budget” true.
    • Otherwise sorted_prices[middle] ≥ budget, so everything at an index ≥ middle is ≥ budget, and high = middle keeps the second half true.
  3. Termination. The loop exits when low == high. Then the invariant says every index is either left of low (and < budget) or at least low (and ≥ budget). So low is exactly the first index with a price ≥ budget. ✓

Separately, we should argue the loop ends: each iteration strictly shrinks high - low, because middle + 1 > low and middle < high.

In KMP the invariant will be, roughly: after reading text[:text_index + 1], the value matched is the length of the longest prefix of the pattern that is a suffix of what we've read. Keep that sentence in mind. Section 13 states it exactly (with one small twist for full matches) and proves it.

medium Euclid's algorithm: while b != 0: a, b = b, a % b, then return a. Write an invariant involving the original inputs \(a_0, b_0\) that proves it returns \(\gcd(a_0, b_0)\).

Solution

Invariant: \(\gcd(a, b) = \gcd(a_0, b_0)\). Initialization is trivial. Maintenance needs \(\gcd(a, b) = \gcd(b, a \bmod b)\). Write \(a = qb + r\) with \(r = a \bmod b\). Any common divisor of \(a\) and \(b\) divides \(r = a - qb\), and any common divisor of \(b\) and \(r\) divides \(a = qb + r\). So the two pairs have the same common divisors, hence the same greatest one. Termination: when \(b = 0\), \(\gcd(a, 0) = a\), so the returned \(a\) equals \(\gcd(a_0, b_0)\).

4. Primer: amortized analysis

KMP's search loop is a while inside a for. The for runs \(n\) times, and a single while can run up to \(m\) times, so a quick glance says \(O(nm)\), which is no better than the naive algorithm. The real bound is \(O(n)\). The technique that shows it is amortized analysis: instead of bounding each iteration's cost separately, we bound the total cost across all iterations.

A familiar example: the sliding window

You have certainly solved LeetCode 3, “longest substring without repeating characters”, with a sliding window. It has the same shape as KMP, an inner while that shrinks the window:

amortized.py
def longest_unique_run(text: str) -> tuple[int, int]:
    """Length of the longest substring without repeated characters (LeetCode 3),
    plus how many times the inner `while` loop ran in total."""
    window_chars: set[str] = set()
    window_start = 0
    best = 0
    inner_steps = 0
    for window_end, char in enumerate(text):
        while char in window_chars:          # shrink until `char` is unique again
            window_chars.remove(text[window_start])
            window_start += 1
            inner_steps += 1
        window_chars.add(char)
        best = max(best, window_end - window_start + 1)
    return best, inner_steps


for text in ["abcabcbb", "aaaaaaaa", "abcdefgh", "abcdefga" * 1000]:
    best, inner_steps = longest_unique_run(text)
    print(f"n={len(text):5}  longest={best}  inner loop steps={inner_steps}")
output
n=    8  longest=3  inner loop steps=7
n=    8  longest=1  inner loop steps=7
n=    8  longest=8  inner loop steps=0
n= 8000  longest=7  inner loop steps=7993

On the 8000-character input the inner loop ran 7993 times in total, less than \(n\). It never comes close to \(n^2 = 64{,}000{,}000\). There are two ways to see why.

The accounting view. Each character enters the window once (in the for) and leaves at most once (in the while). Every inner iteration removes one character that was added earlier, so the inner iterations can't outnumber the additions: at most \(n\).

The potential view. This one generalizes better, so it's the one we'll use for KMP. Choose a quantity \(\Phi\), the “potential”, that measures stored-up work. Here \(\Phi = \) the window size, window_end - window_start + 1 after each step. Then:

  • \(\Phi\) starts at 0 and is never negative.
  • Each outer iteration increases \(\Phi\) by at most 1 (we add one character).
  • Each inner iteration decreases \(\Phi\) by exactly 1 (we remove one character).

Over the whole run, the total decrease can't exceed the total increase, or \(\Phi\) would end up negative:

\[ \#\text{inner iterations} \;\le\; \text{total decrease} \;\le\; \text{total increase} \;\le\; n \cdot 1 = n. \]
The potential-function recipe Find a non-negative quantity \(\Phi\) that starts at 0 (or small), goes up by at most \(c\) per cheap step, and goes down by at least 1 for every unit of expensive work. Then the total expensive work is at most \(c\) times the number of cheap steps. For KMP, \(\Phi\) will be matched: each text character raises it by at most 1, and each fallback in the while lowers it by at least 1.

Practice: amortized analysis

easy For a text of length \(n \ge 1\), what is the largest possible total number of inner-loop iterations in longest_unique_run? Give an input that reaches it.

Solution

\(n - 1\). Each inner iteration removes a character, and the last character added is never removed (the loop ends right after adding it), so at most \(n - 1\) removals happen. medium A binary counter starts at 0 and is incremented \(n\) times. Incrementing flips the trailing 1s to 0 and then one 0 to 1. A single increment can flip many bits (from 0111…1 to 1000…0). Prove the total number of bit flips is at most \(2n\).

Hint

Use \(\Phi\) = the number of 1 bits in the counter.

Solution

Let \(\Phi\) be the number of 1 bits. It starts at 0 and is never negative. An increment that flips \(t\) trailing 1s to 0 and one 0 to 1 does \(t + 1\) flips and changes \(\Phi\) by \(-t + 1\). So every increment raises \(\Phi\) by at most 1, and the total increase over \(n\) increments is at most \(n\). Each of the \(t\) “expensive” flips lowers \(\Phi\) by 1, so the total number of 1→0 flips is at most \(n\). Adding the one 0→1 flip per increment gives at most \(2n\).

The exact count is \(2n - \text{popcount}(n)\). A simulation of \(n = 1000\) gives 1994 flips, and \(\text{popcount}(1000) = 6\).

medium A dynamic array starts with capacity 10 and, when full, grows by +10 (copying all elements). How many element copies happen while appending 1000 elements? Compare with doubling (start at capacity 1). Which one is amortized \(O(1)\) per append, and where does the potential argument break for the other?

Solution

+10 growth resizes when the size reaches 10, 20, …, 990 and copies that many elements: \(10 + 20 + \dots + 990 = 10 \cdot \frac{99 \cdot 100}{2} = 49{,}500\) copies. In general that's about \(n^2/20\), so \(\Theta(n)\) per append on average.

Doubling resizes at 1, 2, 4, …, 512: \(1 + 2 + \dots + 512 = 1023 < 2n\) copies, which is \(O(1)\) amortized.

The potential argument needs every cheap step to “save up” enough for the next expensive one. With doubling, the \(k\) appends between resizes pay for copying about \(k\) elements. With +10, only 10 appends happen between resizes, but the copy costs the whole current size, which keeps growing. No constant-per-step budget covers it.

5. Primer: finite automata

The motivating filter had one requirement: read one character, update a small state, never look back. Machines that do exactly that have a name.

Definition: deterministic finite automaton (DFA) A DFA has a finite set of states, an alphabet Σ of input symbols, a start state, a set of accepting states, and a transition function \(\delta(\text{state}, \text{symbol}) \to \text{state}\) that is defined for every pair. To run it, start in the start state, and for each input symbol in order, replace the current state with \(\delta(\text{state}, \text{symbol})\). It uses \(O(1)\) time per symbol and remembers only the current state.

We'll use DFAs as scanners: after each character, if the machine is in an accepting state, we report “a match ends here”. Here is a DFA over Σ = {a, b} that reports every occurrence of "ab":

The states have a meaning, and that meaning is the whole design: state \(j\) = “the longest suffix of the input read so far that is a prefix of "ab" has length \(j\)”. With that meaning, each arrow is forced:

  • From state 0, an a starts a potential "ab" (go to 1). A b does not (stay at 0).
  • From state 1 (we just saw a), a b completes "ab" (go to 2, accept). Another a doesn't break anything: the input still ends in a, a fresh start (stay at 1).
  • From state 2 (we just saw ab), an a gives an input ending in …aba, whose longest suffix that's a prefix of "ab" is "a" (go to 1). A b gives …abb, and nothing useful survives (go to 0).

6. The problem

With the tools in place, here is the problem stated precisely.

Exact string matching Given a text of length \(n\) and a non-empty pattern of length \(m\), return, in increasing order, every index start with \(0 \le \text{start} \le n - m\) such that text[start:start + m] == pattern. Occurrences may overlap.

Small example: text = "abracadabra", pattern = "abra". The pattern appears at 0 (abracadabra) and at 7 (abracadabra), so the answer is [0, 7]. Overlaps count: "aa" occurs in "aaaa" at [0, 1, 2], not just [0, 2].

Two side remarks before we start. First, the empty pattern is a degenerate case. By convention it occurs at every position \(0, \dots, n\) (Python's "abc".find("") is 0). All the code on this page assumes \(m \ge 1\), and you should special-case \(m = 0\) in real code. Second, nothing below depends on the items being characters. Everything works for any sequence whose elements can be compared for equality: bytes, tokens, log events, DNA bases. Homework 2 asks you to do exactly that.

7. The naive algorithm, and where it wastes work

The direct translation of the definition: for each possible start, compare the pattern with the text character by character, and stop at the first mismatch. I count comparisons so we can measure the waste.

def naive_search(text: str, pattern: str) -> tuple[list[int], int]:
    """All start indices of `pattern` in `text`, plus the number of character comparisons."""
    matches: list[int] = []
    comparisons = 0
    for start in range(len(text) - len(pattern) + 1):
        matched = 0
        while matched < len(pattern):
            comparisons += 1
            if text[start + matched] != pattern[matched]:
                break
            matched += 1
        if matched == len(pattern):
            matches.append(start)
    return matches, comparisons

Diagnosis: what the naive algorithm forgets

Step through the naive algorithm on a repetitive input and watch the text pointer (the orange cell):

Naive search, step by step

Notice how the orange cell keeps jumping backwards. At start = 0 the algorithm matches five characters and then fails at text[5]. Then it moves to start = 1 and starts reading at text[1] again, a character it saw a moment ago.

That's the waste. At the moment of the mismatch we know a lot: the five text characters text[0:5] are exactly "ababa", and text[5] is not 'c'. The naive algorithm throws all of it away. More precisely, it wastes work in two ways:

  1. It re-reads text it has seen. The text pointer moves back from start + matched to start + 1. This is what breaks streaming.
  2. It tries alignments that knowledge already rules out. start = 1 requires text[1] == 'a', but we already know text[1] == 'b'.
The observation everything rests on Everything we know about the text at a mismatch is “the last matched characters equal pattern[:matched]”. So every question about those text characters is really a question about the pattern. Questions about the pattern alone can be answered once, before the search starts, and stored in a table.

8. Warm-up: patterns with no repeated characters

Before the general case, let's remove the waste in an easy special case. That will show what the general fix has to do. Suppose all the characters of the pattern are distinct, like "cat" or "abcd".

We are at alignment start, we've matched \(j \ge 1\) characters, and text[start + j] doesn't match pattern[j]. Could an occurrence start at some start' strictly between start and start + j? It would need text[start'] == pattern[0]. But text[start'] lies inside the matched region, so text[start'] == pattern[start' - start], with \(1 \le \text{start'} - \text{start} < j\). All pattern characters are distinct, so pattern[start' - start] ≠ pattern[0]. So no occurrence starts inside the matched region. The only remaining candidate is the mismatched character itself, start' = start + j: it might be the first character of an occurrence.

So on a mismatch we set matched = 0 and compare the same text character again, this time with pattern[0]. The text pointer never moves back:

warmup.py
def distinct_pattern_search(text: str, pattern: str) -> list[int]:
    """Correct ONLY when all characters of `pattern` are distinct."""
    matches: list[int] = []
    matched = 0
    for text_index, char in enumerate(text):
        if char != pattern[matched]:
            # The matched characters are all different from pattern[0] (distinctness),
            # so no occurrence can start inside them. Only `char` itself might start one.
            matched = 0
        if char == pattern[matched]:
            matched += 1
        if matched == len(pattern):
            matches.append(text_index - len(pattern) + 1)
            matched = 0
    return matches

9. The key insight: borders tell you where to go next

Let's redo the diagnosis in general. We're at alignment start, we've matched matched \(= j \ge 1\) characters, and the next text character, at text_index \(= \text{start} + j\), does not match pattern[j]. (The same reasoning covers a full match, \(j = m\), where we want to keep looking for the next occurrence.) What we know is:

\[ \texttt{text[start : text\_index]} \;=\; \texttt{pattern[:}j\texttt{]}. \]

Now consider a later alignment start' with \(\text{start} < \text{start'} \le \text{text\_index}\). Let \(k = \text{text\_index} - \text{start'}\) be the number of already-read text characters it covers, \(0 \le k < j\). For start' to have any chance, its first \(k\) pattern characters must agree with those \(k\) known text characters:

\[ \texttt{pattern[:}k\texttt{]} \;=\; \texttt{text[start' : text\_index]} \;=\; \texttt{pattern[}j-k\texttt{ : }j\texttt{]}. \]

The second equality holds because those text characters are the last \(k\) of the matched block, which equals pattern[:j]. So the condition reads pattern[:k] == pattern[j-k:j], which says \(k\) is the length of a border of pattern[:j].

Here is the concrete case from the diagnosis, with pattern = "ababaca" and \(j = 5\) characters "ababa" matched. The borders of "ababa" are "aba" (3), "a" (1) and "" (0), so the surviving shifts are \(5-3 = 2\), \(5 - 1 = 4\) and \(5 - 0 = 5\), and the others are dead on arrival:

The key insight After matching \(j\) characters, the only alignments worth trying correspond to the borders of pattern[:j]. For a border of length \(k\):
  1. its first \(k\) characters are already known to match, so we don't compare them again;
  2. the next comparison is text[text_index] against pattern[k], so the text pointer does not move back;
  3. to avoid skipping an occurrence, try the borders from longest to shortest, because a longer border means a smaller shift.
In terms of our one variable, a mismatch turns matched = j into matched = k.

Notice what happened to the problem. Deciding where to go next no longer involves the text at all. It's a question about the pattern: “what are the borders of pattern[:j]?”. There are only \(m\) possible values of \(j\), so we can answer them all in advance. Two pieces are left:

  1. A table giving the longest border of every prefix of the pattern. This is the prefix function π.
  2. A way to get the next shorter border when the longest one also fails against text[text_index]. It turns out the same table gives that too.

10. The prefix function and the border chain

Definition: prefix function π For a pattern of length \(m\) and each index \(q = 0, 1, \dots, m-1\): \[ \pi[q] \;=\; \text{the length of the longest proper border of } \texttt{pattern[:}q+1\texttt{]}. \] Here \(q\) is the index of the last character of the prefix, so pattern[:q+1] has length \(q + 1\). In code this is the list longest_border, with longest_border[q] \(= \pi[q]\).

Detour: one function, many names You'll meet this table under several names and indexings, which makes comparing sources confusing. CLRS calls it the prefix function \(\pi[q]\) for the 1-indexed prefix \(P[1..q]\). That's the same numbers as ours, with the index shifted by one. Knuth's original paper uses next[j], which is a slightly optimized variant (see Section 14) with a sentinel value. Many textbooks call it the failure function, and cp-algorithms uses exactly our 0-indexed π. When you read code, always check what the index means.

The border chain

π gives the longest border. When that one also fails, the key insight says to try the next one. Here is the lemma that makes that cheap.

Border chain lemma Let \(u\) be the longest proper border of \(w\). Then the proper borders of \(w\) are exactly: \(u\), and the proper borders of \(u\). Applied repeatedly, the border lengths of pattern[:j] from longest to shortest are \[ \pi[j-1],\quad \pi[\pi[j-1]-1],\quad \pi[\pi[\pi[j-1]-1]-1],\quad \dots,\quad 0. \]

Proof. There are two directions.

  1. Every border of \(u\) is a border of \(w\). This is “a border of a border is a border”, which you proved in the borders practice (Section 2).
  2. Every border \(c\) of \(w\) shorter than \(u\) is a border of \(u\). \(c\) and \(u\) are both prefixes of \(w\). Two prefixes of the same string are nested: the shorter one is a prefix of the longer one. So \(c\) is a prefix of \(u\). In the same way, \(c\) and \(u\) are both suffixes of \(w\), so \(c\) is a suffix of \(u\). And \(|c| < |u|\), so \(c\) is a proper border of \(u\).

So the borders of \(w\) are \(u\) together with the borders of \(u\). The longest border of \(u\) is π of the prefix \(u\), whose last index is \(|u| - 1\). Applying the lemma to \(u\), then to its longest border, and so on, walks down every border in decreasing order. The lengths strictly decrease, so the walk ends at 0. ∎

Plugged into the key insight, this says: on a mismatch with matched = j, try matched = π[j-1]. If that also mismatches, try π[matched-1] again, and so on, until a comparison succeeds or matched reaches 0. That is a while loop, and it is the whole search algorithm. Before writing it, we need π itself, fast.

11. Computing π in linear time

The slow version recomputes every border from scratch, \(O(m^2)\) candidate lengths each costing up to \(O(m)\), so \(O(m^3)\). The fast version reuses earlier entries, through one observation about how borders grow.

Borders grow one character at a time If pattern[:q+1] has a border of length \(k \ge 1\), then dropping the last character gives a border of length \(k-1\) of pattern[:q], and the character after that shorter border is pattern[k-1] == pattern[q]. The converse also holds: if \(b\) is a border length of pattern[:q] and pattern[b] == pattern[q], then \(b+1\) is a border length of pattern[:q+1].

Spelled out: “\(k\) is a border length of pattern[:q+1]” means pattern[0:k] == pattern[q+1-k:q+1]. Two strings are equal exactly when they're equal without their last character and the last characters also agree. So the condition splits into pattern[0:k-1] == pattern[q+1-k:q] (a border of length \(k-1\) of pattern[:q]) and pattern[k-1] == pattern[q]. Both directions follow from the same split.

So to find \(\pi[q]\), take the borders \(b\) of pattern[:q] from longest to shortest, and pick the first one whose next character pattern[b] equals pattern[q]. The answer is \(b + 1\), or 0 if no border works. By the chain lemma, the borders of pattern[:q] from longest to shortest are \(\pi[q-1], \pi[\pi[q-1]-1], \dots, 0\), and all of those entries are already computed because they sit at smaller indices.

prefix_function.py
import random


def prefix_function(pattern: str) -> list[int]:
    """longest_border[end] = length of the longest proper border of pattern[:end + 1]."""
    longest_border = [0] * len(pattern)
    for end in range(1, len(pattern)):
        # Candidates are the borders of pattern[:end], longest first, each extended by pattern[end].
        candidate = longest_border[end - 1]
        while candidate > 0 and pattern[end] != pattern[candidate]:
            candidate = longest_border[candidate - 1]   # next shorter border of pattern[:end]
        if pattern[end] == pattern[candidate]:
            candidate += 1
        longest_border[end] = candidate
    return longest_border


def prefix_function_slow(pattern: str) -> list[int]:
    result: list[int] = []
    for end in range(len(pattern)):
        word = pattern[:end + 1]
        result.append(max(k for k in range(len(word)) if word[:k] == word[len(word) - k:]))
    return result

12. The KMP search

We now have every piece: the variable matched, the rule “on a mismatch, fall back along the border chain”, and the table π that makes each fallback one array lookup. Here is the whole algorithm:

kmp.py
def prefix_function(pattern: str) -> list[int]:
    longest_border = [0] * len(pattern)
    for end in range(1, len(pattern)):
        candidate = longest_border[end - 1]
        while candidate > 0 and pattern[end] != pattern[candidate]:
            candidate = longest_border[candidate - 1]
        if pattern[end] == pattern[candidate]:
            candidate += 1
        longest_border[end] = candidate
    return longest_border


def kmp_search(text: str, pattern: str) -> tuple[list[int], int]:
    """All start indices of a non-empty `pattern` in `text`, plus the comparison count."""
    longest_border = prefix_function(pattern)
    matches: list[int] = []
    comparisons = 0
    matched = 0                       # invariant: text[..text_index] ends with pattern[:matched]
    for text_index, char in enumerate(text):
        while matched > 0 and char != pattern[matched]:
            comparisons += 1
            matched = longest_border[matched - 1]      # fall back to the next shorter border
        comparisons += 1
        if char == pattern[matched]:
            matched += 1
        if matched == len(pattern):
            matches.append(text_index - len(pattern) + 1)
            matched = longest_border[matched - 1]      # keep overlapping occurrences alive
    return matches, comparisons

Line by line, for each text character char at text_index:

  1. Fall back while we must. If some prefix is matched (matched > 0) but char doesn't extend it, replace matched with the next shorter border, longest_border[matched - 1], and try again. The text pointer stays put.
  2. Extend if we can. If char == pattern[matched], one more character is matched. If matched is 0 and the comparison fails, nothing happens: this character can't start an occurrence, and we move on.
  3. Report and keep going. If matched reached \(m\), an occurrence ends at text_index, so it starts at text_index - m + 1. Then fall back to longest_border[m - 1] rather than 0, so that an overlapping occurrence (like the second "aa" in "aaaa") is not lost.

The pattern + "#" + text trick

Since the search is “the prefix function, applied across the boundary between pattern and text”, you can skip writing the search loop entirely: glue the strings together with a separator that occurs in neither, compute π of the result, and look for entries equal to \(m\).

def prefix_function(pattern: str) -> list[int]:

        candidate = longest_border[end - 1]

def find_all_via_concat(text: str, pattern: str, separator: str = "#") -> list[int]:
    """Requires `separator` to occur in neither string."""
    combined = pattern + separator + text
    longest_border = prefix_function(combined)
    m = len(pattern)
    return [
        end - 2 * m                     # end is in `combined`; shift back to a start in `text`
        for end in range(len(combined))
        if longest_border[end] == m
    ]

Why it works: an entry \(\pi[e] = m\) in combined means the last \(m\) characters ending at \(e\) equal the first \(m\), which is the pattern. The separator guarantees that no border can be longer than \(m\): a border longer than \(m\) would have to contain the # as a prefix character, and the # can't appear again in the text part. This version is popular in competitive programming because it's one function and one comprehension. It uses \(O(n + m)\) memory instead of \(O(m)\), and it can't stream, so prefer the real loop in production.

13. Why it is correct

The proof is the invariant promised in Section 3. The careful statement is:

Invariant At the top of the loop iteration for text_index, matched is the length of the longest proper prefix of the pattern (length \(< m\)) that is a suffix of text[:text_index], the text read so far.

We check the three duties.

Initialization. At text_index = 0 nothing has been read, and the only suffix of the empty string is the empty string, so the answer is 0, which is matched's initial value. ✓

Maintenance. Assume the invariant for text_index. Let char = text[text_index] and \(R\) = text[:text_index]. We want the longest prefix of the pattern that is a suffix of \(R\) + char.

  1. A non-empty prefix pattern[:b+1] is a suffix of \(R\) + char exactly when pattern[:b] is a suffix of \(R\) and pattern[b] == char. This is the same “split off the last character” argument as in Section 11.
  2. Which values of \(b\) make pattern[:b] a suffix of \(R\)? Certainly \(b =\) matched. If \(b\) is smaller, then pattern[:b] and pattern[:matched] are both suffixes of \(R\), so the shorter one is a suffix of the longer one. It's also a prefix of it, so it's a border of pattern[:matched]. By the chain lemma, the candidates for \(b\) are exactly matched, π[matched-1], …, 0, in decreasing order.
  3. The while loop visits exactly these candidates in exactly this order, and stops at the first \(b\) with pattern[b] == char (or at 0). The if then sets matched to \(b + 1\) if that comparison succeeds, otherwise 0. So after the if, matched is the longest prefix of the pattern that is a suffix of \(R\) + char, which can now be as long as \(m\).
  4. If matched == m, we report, then set matched = π[m-1]. Every proper prefix that is a suffix of \(R\) + char is then a suffix of the pattern (which is itself the suffix), so it's a border of the pattern. The longest one has length π[m−1]. So the invariant (with “proper”) holds again for the next iteration. ✓

Termination: what it reports. By step 3, right after the if, matched == m holds exactly when the whole pattern is a suffix of text[:text_index + 1], that is, exactly when an occurrence ends at text_index. So every occurrence is reported, once, at the moment it ends, and nothing else is reported. The for loop obviously terminates. The while loop terminates because matched strictly decreases in it and can't go below 0. ∎

The sentence to remember matched is “how much of the pattern the text currently ends with”, and the border chain lists every smaller answer in order. Correctness is just checking that the code keeps that meaning.

14. Running time, and what “linear” hides

The search is \(O(n)\). Use the potential method with \(\Phi =\) matched:

  • \(\Phi\) starts at 0 and never goes below 0.
  • It increases only in matched += 1, at most once per text character, so the total increase is at most \(n\).
  • Every fallback, in the while or after a report, strictly decreases it, because \(\pi[j-1] < j\).

So there are at most \(n\) fallbacks in total. Each costs one comparison, and each text character also has one comparison in the if:

\[ \text{comparisons} \;\le\; \underbrace{n}_{\text{the } \texttt{if}} + \underbrace{n}_{\text{all fallbacks}} \;=\; 2n. \]

Building π is \(O(m)\), by the identical argument (Section 11). Together that's \(O(n + m)\) time, with \(O(m)\) extra memory for the table, independent of the text length. That's what lets the stream matcher from Section 1 run forever on a fixed budget.

The measured numbers: on the adversarial input (\(n = 10{,}000\), \(m = 100\)), 19,901 comparisons for KMP against 990,100 for naive. On 20,000 random small inputs over {a, b}, the worst ratio of comparisons to \(2n\) was 0.94, and the second practice problem below shows the bound is essentially tight.

What “amortized” hides: per-character delay

The \(2n\) bound is for the total. A single text character can still trigger a long chain of fallbacks. With pattern = "aaab" and text = "aaac", the c causes 3 fallbacks (3 → 2 → 1 → 0), in general \(m - 1\). For a batch search that doesn't matter. For a hard real-time system, like a router that must forward each byte within a fixed time, the worst case per character matters.

Detour: the optimized (“strong”) failure function Look at the fallback 3 → 2 → 1 → 0 above. The c fails against pattern[3] = 'b', then against pattern[2] = 'a'. The next two comparisons are against pattern[1] = 'a' and pattern[0] = 'a', the same letter that just failed, so they are doomed before they start. Knuth's version of the table (next in the original paper) skips a border \(b\) whenever pattern[b] == pattern[j], because the character that just failed against pattern[j] would fail against pattern[b] too. With that change, the 1977 paper shows the number of fallbacks for one character is \(O(\log m)\) (more precisely, about \(\log_\phi m\) with \(\phi\) the golden ratio). Going all the way removes the while entirely and gives exactly one step per character. That's the DFA of the next section.

Practice: complexity

easy The while loop can run \(m - 1\) times on a single character. Why doesn't that give an \(O(nm)\) bound in the worst case?

Solution

To fall back \(m-1\) times, matched must first have climbed to \(m - 1\), which took \(m - 1\) earlier characters, each raising it by exactly 1. Long fallbacks are “paid for” by the characters that built up the match, and each unit of matched can be spent only once. Only the total matters: at most \(n\) climbs, so at most \(n\) falls.

medium Show that KMP in fact never needs more than \(2n - 1\) comparisons, and find a family of inputs that uses exactly \(2n - 1\) for every \(n \ge 1\).

Hint

Which climbs of matched can ever be paid back by a fallback? Try the pattern "ab".

Solution

Upper bound. A fallback while processing character \(i\) spends units of matched that were gained while processing characters \(0, \dots, i-1\). The climb gained at the last character (\(i = n-1\)) can never be spent, because no character comes after it. So total fallbacks \(\le\) climbs at characters \(0..n-2\) \(\le n - 1\), and comparisons \(\le n + (n - 1) = 2n - 1\).

Tight family. text = "a" * n, pattern = "ab", π = [0, 0]. The first a costs 1 comparison (matched becomes 1). Every later a is compared with pattern[1] = 'b' (fail), falls back to 0, and is compared with pattern[0] = 'a' (success): 2 comparisons. Total \(1 + 2(n-1) = 2n - 1\). A brute-force search over all texts of length 8 and patterns of length 2 and 3 over {a, b} confirms that 15 \(= 2 \cdot 8 - 1\) is the maximum, reached for example by ("aaaaaaaa", "ab").

15. KMP as an automaton

Go back to the DFA primer. There, a state meant “the longest suffix of the input that is a prefix of the target”. That is word for word our invariant for matched. So KMP is a DFA with states \(0, 1, \dots, m\). It just doesn't store the transition table. It recomputes each transition on the fly by walking failure links. If we precompute the table instead, every character costs exactly one lookup.

The table follows from the same rule the while loop applies:

\[ \delta(j, c) = \begin{cases} j + 1 & \text{if } j < m \text{ and } \texttt{pattern}[j] = c \quad\text{(forward edge)}\\ 0 & \text{if } j = 0 \text{ and } \texttt{pattern}[0] \ne c \\ \delta(\pi[j-1],\, c) & \text{otherwise (copy the row of the fallback state)} \end{cases} \]

Here \(j\) is a state (the number of matched characters) and \(c\) is a character. The third case is the whole trick. “Mismatch at state \(j\)” means “behave exactly as state \(\pi[j-1]\) would on the same character”. Since \(\pi[j-1] < j\), that row is already built if we fill rows in increasing order.

dfa.py
def prefix_function(pattern: str) -> list[int]:
    longest_border = [0] * len(pattern)
    for end in range(1, len(pattern)):
        candidate = longest_border[end - 1]
        while candidate > 0 and pattern[end] != pattern[candidate]:
            candidate = longest_border[candidate - 1]
        if pattern[end] == pattern[candidate]:
            candidate += 1
        longest_border[end] = candidate
    return longest_border


def build_dfa(pattern: str, alphabet: str) -> list[dict[str, int]]:
    """transitions[state][char] for states 0..len(pattern); state = chars matched so far."""
    longest_border = prefix_function(pattern)
    transitions: list[dict[str, int]] = []
    for state in range(len(pattern) + 1):
        row: dict[str, int] = {}
        for char in alphabet:
            if state < len(pattern) and pattern[state] == char:
                row[char] = state + 1                      # forward edge
            elif state == 0:
                row[char] = 0
            else:
                fallback = longest_border[state - 1]       # fallback < state: row already built
                row[char] = transitions[fallback][char]
        transitions.append(row)
    return transitions


def dfa_search(text: str, pattern: str, alphabet: str) -> list[int]:
    transitions = build_dfa(pattern, alphabet)
    state = 0
    matches: list[int] = []
    for text_index, char in enumerate(text):
        state = transitions[state][char]                    # exactly one lookup per char
        if state == len(pattern):
            matches.append(text_index - len(pattern) + 1)
    return matches

Detour: why this connects to regular expressions After each character, a scanner asks “does the input read so far end with the pattern?”. That's one reason regex engines special-case literal substrings.

16. Pitfalls

KMP is about twelve lines, and most of them can be wrong in a way that passes simple tests. Here are the classic mistakes, most of them demonstrated on real code:

pitfalls.py
def prefix_function(pattern: str) -> list[int]:
    longest_border = [0] * len(pattern)
    for end in range(1, len(pattern)):
        candidate = longest_border[end - 1]
        while candidate > 0 and pattern[end] != pattern[candidate]:
            candidate = longest_border[candidate - 1]
        if pattern[end] == pattern[candidate]:
            candidate += 1
        longest_border[end] = candidate
    return longest_border


def search(text: str, pattern: str, *, single_fallback: bool = False,
           reset_after_match: bool = False) -> list[int]:
    longest_border = prefix_function(pattern)
    matches: list[int] = []
    matched = 0
    for text_index, char in enumerate(text):
        if single_fallback:
            if matched > 0 and char != pattern[matched]:       # BUG: `if` instead of `while`
                matched = longest_border[matched - 1]
        else:
            while matched > 0 and char != pattern[matched]:
                matched = longest_border[matched - 1]
        if char == pattern[matched]:
            matched += 1
        if matched == len(pattern):
            matches.append(text_index - len(pattern) + 1)
            matched = 0 if reset_after_match else longest_border[matched - 1]
    return matches

1. if instead of while for the fallback One fallback is not enough when the next border also fails. Worse than missing matches, it produces false positives. On "aabaa" with the pattern "aaa", at the b the buggy version falls back once (2 → 1), doesn't compare again, and leaves matched = 1 even though the text now ends in b. The next two as then “complete” a match that doesn't exist, and it reports [2].
2. Resetting to 0 after a match matched = 0 after reporting loses overlapping occurrences: "aaaa"/"aa" gives [0, 2] instead of [0, 1, 2]. That's correct only if you want non-overlapping matches, as str.count and str.replace do.
3. π[matched] instead of π[matched - 1] This mixes up “length” and “last index”. It runs, it often gives right answers, and then it reports [0, 3] for "ababaab"/"abab" (3 is wrong). On other inputs it loops forever (try "aabaaab"/"aab"). See the practice problem below.
4. Dropping the matched > 0 guard In Python, longest_border[0 - 1] is longest_border[-1], the last entry. There's no IndexError, just silently wrong jumps. With pattern = "ab" it becomes an infinite loop on "xab", because matched keeps being set to π[−1] = 0 and the comparison keeps failing.
5. Starting the π loop at index 0 for end in range(0, m) computes π[0] = 1 (the whole one-character string counted as its own border), which is not a proper border. Fallback from 1 then goes to π[0] = 1 forever. π[0] is always 0. Start at 1.
6. Mixing conventions from different sources CLRS is 1-indexed, Knuth's next uses −1 as a sentinel and the optimized rule, and cp-algorithms is 0-indexed like this page. Copying the build from one source and the search from another is a reliable way to get an off-by-one. Pick one convention and test both halves against brute force on random small strings over a two-letter alphabet.
7. The empty pattern, and the separator prefix_function("") returns [], and kmp_search then crashes on pattern[0]. Special-case \(m = 0\). For the concatenation trick, the separator must occur in neither string. For arbitrary data (bytes, tokens) use a list with a sentinel object, like [*pattern, None, *text], rather than hoping "#" is unused.

17. Applications: what π is good for beyond search

On LeetCode-style problems, π is often more useful than the search itself, because it answers questions about a string's structure: periods, repeats, self-overlaps. Here are the standard ones:

def prefix_function(pattern: str) -> list[int]:

Longest happy prefix (LeetCode 1392)

“The longest proper prefix that is also a suffix” is literally the definition of the last π entry: word[:π[m-1]]. It's \(O(m)\) and one line. The problem is a good self-test that you remember what π means.

Repeated substring pattern (LeetCode 459)

Is word some block repeated two or more times? Let \(p = m - \pi[m-1]\) be the shortest period (Section 2). The answer is yes exactly when \(p < m\) and \(p\) divides \(m\). If \(p\) divides \(m\), the word is word[:p] repeated \(m/p\) times, which is easy to see. The other direction, that if any block repeats then the shortest period divides \(m\), needs the Fine–Wilf periodicity lemma: if \(p\) and \(q\) are both periods and \(p + q \le m + \gcd(p, q)\), then \(\gcd(p, q)\) is also a period. With \(q\) the block length (\(q \le m/2\)) and \(p \le q\), that gives that \(\gcd(p, q)\) is a period, so it equals \(p\) (nothing shorter is a period), so \(p\) divides \(q\), which divides \(m\). Note "abcabcab": period 3, but 3 doesn't divide 8, so the answer is False.

Shortest palindrome (LeetCode 214)

Add the fewest characters in front of word to make it a palindrome. That's equivalent to finding the longest palindromic prefix word[:k], then prepending the reverse of the rest. The trick: word[:k] is a palindrome exactly when it equals its own reverse, and the reverse of word[:k] is the suffix of length \(k\) of word[::-1]. So the longest palindromic prefix is the longest prefix of word that is a suffix of word[::-1]. That's π of word + "#" + word[::-1] at the last index, the concatenation trick again. The # stops the border from being longer than word.

Rotations and repeats (LeetCode 796, 686)

goal is a rotation of word exactly when the lengths are equal and goal occurs in word + word, which is one KMP search, \(O(m)\). For 686 (how many copies of a must be concatenated so that b is a substring), only \(\lceil |b|/|a| \rceil\) or one more copy can work. Search b in that many copies. For a = "abcd", b = "cdabcdab" the answer is 3.

hard For each prefix length \(k = 1..m\), count how many times word[:k] occurs in word, in \(O(m)\) total. (Example: in "abab", "a" occurs 2 times, "ab" 2, "aba" 1, "abab" 1.)

Hint

Every occurrence of word[:k] ending at index \(e\) is a border of word[:e+1] (or the whole prefix when \(e = k-1\)). The occurrences ending at \(e\) are exactly the border chain from π[e]. Push counts down the chain from long to short.

Solution 
def prefix_occurrences(word: str) -> list[int]:
    longest_border = prefix_function(word)
    m = len(word)
    count = [0] * (m + 1)
    for end in range(m):
        count[longest_border[end]] += 1      # top of the chain ending at `end`
    for length in range(m, 0, -1):            # push counts down, longest first
        count[longest_border[length - 1]] += count[length]
    for length in range(1, m + 1):
        count[length] += 1                    # the prefix itself
    return count[1:]

Why it works: the prefixes that end at index \(e\) are word[:e+1] itself plus the whole border chain π[e], π[π[e]−1], …. The first loop records the top of each chain. The second loop propagates each count to the next border down. Processing lengths from long to short works because π[length−1] < length. The last loop adds the prefix itself. For "abab" it gives [2, 2, 1, 1], and this was checked against brute-force counting on random strings. (count[0] collects junk from borders of length 0 and is discarded.)

18. Alternatives and extensions

KMP is rarely the fastest choice in practice. Its value is the worst-case guarantee, the streaming property, and the ideas it introduced. Here's how it relates to its neighbours.

The Z-function: same power, different shape

The Z-function stores, for every position \(i\), the length of the longest common prefix of the string and its suffix starting at \(i\). Where π looks backwards from each position (“which prefix ends here?”), Z looks forwards (“how much of a prefix starts here?”).

z_function.py
def z_function(word: str) -> list[int]:
    """z[i] = length of the longest common prefix of word and word[i:]; z[0] = 0 by convention."""
    z = [0] * len(word)
    box_left, box_right = 0, 0          # word[box_left:box_right] is a prefix copy found earlier
    for index in range(1, len(word)):
        if index < box_right:
            z[index] = min(box_right - index, z[index - box_left])
        while index + z[index] < len(word) and word[z[index]] == word[index + z[index]]:
            z[index] += 1
        if index + z[index] > box_right:
            box_left, box_right = index, index + z[index]
    return z


def z_search(text: str, pattern: str) -> list[int]:
    combined = pattern + "#" + text
    z = z_function(combined)
    return [index - len(pattern) - 1 for index in range(len(combined)) if z[index] == len(pattern)]


print(z_function("aabxaab"))
print(z_search("abracadabra", "abra"))
output
[0, 1, 0, 0, 3, 1, 0]
[0, 7]

The speed-up mirrors KMP's. The algorithm remembers the Z-box [box_left, box_right), the rightmost segment found so far that equals a prefix of the string. If \(i\) is inside the box, then word[i:box_right] is a copy of word[i - box_left : box_right - box_left], so \(z[i]\) is at least \(\min(\text{box\_right} - i,\; z[i - \text{box\_left}])\) for free. Characters are only compared past box_right, and each successful comparison pushes box_right right. That's the same potential argument, and gives \(O(n)\) in total.

Use Z when you need the whole array (for example, “for each suffix, how long a prefix does it start with?”). Use π when data streams, since Z needs the whole string up front. Each array can be converted into the other in \(O(n)\).

What does Python do? CPython's str.find (in Objects/stringlib/fastsearch.h) uses a Boyer–Moore–Horspool hybrid with a Bloom-filter skip for short needles and haystacks. So in is safe against the adversarial input from Section 7. You'd write KMP yourself when you need streaming, custom item types, the π array itself, or the automaton.

Aho–Corasick: KMP for many patterns

Back to the motivating filter. A real IDS has thousands of signatures, not one. Running thousands of KMPs side by side costs time proportional to the number of patterns for every byte. Aho–Corasick (1975) merges them: put all the patterns into a trie, and give every trie node a failure link to the node for the longest proper suffix of its string that is also in the trie. That is exactly π, generalized from a line of states to a tree.

Scanning works exactly like KMP: follow a trie edge if one exists for the next character, otherwise follow failure links until one does (or you're at the root). Failure links are computed in BFS order, just as π is computed left to right, because a node's link points to a shallower node. One extra wrinkle: a node can end a pattern “inside” it. When you reach she, the pattern he also ends there. So each node also keeps an output link to the nearest node on its failure chain that ends a pattern. Implementing this is Homework 1.

Other places the idea shows up

  • Any comparable items. KMP works on lists of tokens, events or rows, wherever == is defined. Homework 2.
  • Paths in trees. Carry matched down a DFS, and it is restored automatically on backtrack because it's a local variable. LeetCode 1367, Homework 3.
  • Counting strings that avoid a pattern. The automaton from Section 15 is the state of a DP over “how much of the forbidden word have I just written”. LeetCode 1397 (Find All Good Strings) is the hard version.
  • 2-D matching (Bird 1977, Baker 1978). Label each text row position with Aho–Corasick, then run KMP down the columns on those labels. Homework 5.

19. Summary

The state. matched = length of the longest prefix of the pattern that the text read so far ends with. It's the only thing remembered.
The table. \(\pi[q]\) = longest proper border of pattern[:q+1]. On a mismatch with \(j\) matched, go to \(\pi[j-1]\), then keep following the chain.
Why borders. After matching \(j\) characters, the only alignments that can succeed overlap the matched block in a border of pattern[:j], and the chain lists them all, longest first.
Why linear. matched rises by ≤ 1 per character and every fallback lowers it, so there are ≤ \(n\) fallbacks and ≤ \(2n - 1\) comparisons. π takes \(O(m)\) by the same argument.
Same loop twice. Building π is matching the pattern against itself. π(pattern + "#" + text) == m marks occurrences.

easy Q1. Compute π for "abcabd".

Solution

[0, 0, 0, 1, 2, 0]. a, ab, abc have no non-empty border. abca has a, abcab has ab. For abcabd, extending ab needs pattern[2] = 'c' = 'd', no. Extending "" needs pattern[0] = 'a' = 'd', no. So 0.

easy Q2. Searching for "abcabd", the text so far ends with "abcab" (matched = 5) and the next character is 'c'. What is matched afterwards, and which comparisons happen?

Solution

'c' vs pattern[5] = 'd' fails, so fall back to π[4] = 2. 'c' vs pattern[2] = 'c' succeeds, so matched = 3. Check with the meaning: the text now ends with "abcabc", and its longest suffix that starts the pattern is "abc" ✓.

easy Q3. True or false: during KMP's search, the index of the text character being compared can decrease.

Solution

False. Fallbacks change only matched, which is which pattern character we compare against. The text index only advances, in the for loop. That's the streaming property. (The alignment text_index - matched moves right on a fallback, never left.)

medium Q4. What is the shortest period of "abaababaab"? Is it a repetition of a smaller block (LeetCode 459)?

Solution

π ends in 5 (the border "abaab"), so the shortest period is \(10 - 5 = 5\), which divides 10. It's "abaab" twice, so yes. (π = [0,0,1,1,2,3,2,3,4,5], computed by the code.)

medium Q5. How many comparisons does kmp_search("a" * 10, "aaa") make, and what does it return?

Solution

π = [0,1,2]. The first three as each match (3 comparisons), and the third completes a match, which falls back to 2. Each later a matches pattern[2] straight away, completes a match, and falls back to 2: 1 comparison each. Total 10, occurrences [0, 1, …, 7]. Fallbacks after a report aren't comparisons. The output was ([0, 1, 2, 3, 4, 5, 6, 7], 10).

medium Q6. Over the alphabet {a, b}, a pattern starting with a has π = [0, 1, 2, 3]. What is it? What about π = [0, 0, 1, 2, 3]?

Solution

"aaaa": every step extends the previous border, so each new character equals pattern[π[q-1]] = a. For [0,0,1,2,3]: pattern[1] must differ from a, so it's b. Then each next character copies pattern[π[q-1]]: pattern[2] = pattern[0] = a, pattern[3] = pattern[1] = b, pattern[4] = pattern[2] = a. That gives "ababa".

medium Q7. Pick the best tool: (a) flag any of 10,000 banned words in a chat stream; (b) find one 30-letter phrase in a 1 GB English text file, as fast as possible on average; (c) run millions of queries against one fixed genome; (d) detect one 8-byte signature in a byte stream, with a hard per-byte time budget.

Solution

(a) Aho–Corasick: one pass for all patterns. (b) Boyer–Moore/Horspool-style skipping, or just your language's built-in find, which does this. Long pattern and big alphabet means big skips. (c) Preprocess the text instead: a suffix array or FM-index, then each query costs time in the pattern length, not the genome length. hard Q8. Prove or refute: if \(\pi[m-1] > m/2\), then the pattern has a border of length exactly \(2\pi[m-1] - m\).

Hint

Think periods. A border of length \(b\) means period \(p = m - b\). What does a period do to a border?

Solution

True. Let \(b = \pi[m-1]\) and \(p = m - b < m/2\) the period. The border \(u\) = pattern[:b] is a prefix of the pattern, so it inherits the period \(p\) (the condition w[i] == w[i+p] for \(i + p < b\) is a subset of the original conditions). A string of length \(b\) with period \(p < b\) has a border of length \(b - p\). So \(u\) has a border of length \(b - p = 2b - m\), and a border of a border is a border. Example: "abababa", \(b = 5\), \(m = 7\): it should have a border of length \(2\cdot 5 - 7 = 3\), and "aba" is one ✓. "aaaa": \(b = 3\), so length 2 is a border ✓. In general the chain of a highly periodic string steps down by \(p\) each time while the border stays longer than \(p\).

22. History

The algorithm has an unusually tangled origin. In 1969 Yuri Matiyasevich, working on a pattern-recognition problem over a binary alphabet, found a linear-time matching procedure expressed as a two-dimensional Turing machine. It's generally credited as the first linear-time string-matching algorithm. Independently, James H. Morris conceived the failure-function idea, and he and Vaughan Pratt wrote it up as a Berkeley technical report, “A linear pattern-matching algorithm”, in 1970.

Donald Knuth got there by a remarkable route. Stephen Cook had shown in the early 1970s that any language recognized by a two-way deterministic pushdown automaton can be recognized in linear time on a random-access machine. String matching is easy to express as such an automaton. Knuth traced through Cook's simulation for that particular automaton and extracted a linear-time matching algorithm from it. It was essentially the same algorithm. The three published together as “Fast Pattern Matching in Strings” in the SIAM Journal on Computing in 1977. The paper also contains the optimized next table and its \(O(\log m)\) delay bound, and discussion of periodicity.

1977 was a good year for the field. Boyer and Moore published their right-to-left algorithm the same year. Aho and Corasick had already (1975) generalized the failure-link idea to many patterns at once, and it went into Unix's fgrep. Crochemore and Perrin's Two-Way algorithm (1991) later achieved linear time with constant extra space, and that's what glibc and CPython use today.
